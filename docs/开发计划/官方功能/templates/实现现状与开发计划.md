> 依据：官网 [SciNote Templates](https://www.scinote.net/product/scinote-templates/) 六大模板类型功能清单 + 本仓（`scinote-web`）源码探查 + **addon 二次开发铁律**（`docs/development/addon-dev-workflow.md`）。
> 方法学：同 `docs/development/addon-dev-workflow.md`（Phase 0–6）；术语与 ADR 约定见 `docs/ARCHITECTURE_DECISIONS.md` 第三节（现有 0008…0015，本计划新增 **0016**）。
> 配套特性文档：[README.md](./README.md)（含本地图片）。

## 一、结论

**SciNote Templates 是 SciNote 的核心能力，本仓已基本完整实现（约 95%）。** 与 Protocol & SOP Management（`docs/开发计划/官方功能/protocol-sop-management/`）类似，本页描述的是既有产品功能，并非本 fork 的绿地需求——六大模板类型中的五类均已落在核心 `app/`，并受既有 `app/permissions/**` 权限模型与对应数据模型支撑。

因此本计划**不做「从零造」式的整体 addon**，仅针对官网描述中**底层已实现、但缺少一等公民（first-class）封装**的一点（Item Templates 的命名可复用抽象）给出增强型 addon 形态开发计划。注意：官网 "Automatically prompt users to use correct pre-approved reagents, instruments, kits" 的**自动提示行为已由核心实现**（`ProtocolRepositoryRow`→`MyModuleRepositoryRow` 实例化拷贝，见证据表），本 addon 不重复该能力，仅补「可复用抽象 + 可选 `required` 标志」：

| 缺口 | 严重度 | 是否 addon 可承接 |
|---|---|---|
| **T1 命名可复用的「物料模板（Item Templates）」抽象** —— 底层「协议挂库存项 + 实例化自动带入任务」**已实现**（`ProtocolRepositoryRow`→`MyModuleRepositoryRow`，见证据表）；缺失的是把「一套预选库存」抽象成**命名、可复用、可绑定多协议**的一等公民对象，以及 optional `required` 强制标志 | 低 | ⚠️ 增强型 addon（非绿地重建） |
| **T2 Forms 嵌入协议步骤的「协议级物料/字段联动」** | 信息项 | 现有，无需新建 |

> 与「AI 辅助生成协议模板」属另一独立绿地工作，已在 `0013` + `docs/ai-eln/实现现状与开发计划.md` 规划（`addons/ai_protocols`），本计划不重复展开。
> 与「协议库版本变更通知」属 `docs/开发计划/官方功能/protocol-sop-management/` 规划的 **G1**（addon `protocol_version_notifier`，**0017**），本计划不重复。

## 三、已核实技术接缝（addon 接入点）

- **A — 协议级库存关联（核心插入点）**：`Protocol` 已有 `has_many :protocol_repository_rows`（`app/models/protocol.rb:142-143`），经 `ProtocolRepositoryRow`（`app/models/protocol_repository_row.rb`）关联 `repository_rows`；协议链接到任务时，行会随 `protocol_repository_rows` 拷贝到模块（`protocol.rb:448-451`）。addon 可在引擎 `to_prepare` 中装饰协议模板的「实例化」动作，从绑定的 Item Template 自动建立 `protocol_repository_rows`，**不碰核心创建逻辑**。
- **B — 库存模板复用（复用，不新建）**：`RepositoryTemplate`（`app/models/repository_template.rb`）已建模列定义与预定义模板；Item Template 可直接引用某个 `RepositoryTemplate` 或一组预选 `repository_rows`，无需新建库存数据模型。
- **C — 权限（复用，不加新权限）**：协议读/管理权限已齐备（`app/permissions/protocol.rb`）；库存模板读权限在 `app/permissions/repository.rb`。addon 复用既有 `can_read_protocol_in_repository?` / 库存权限判定，不新增角色。
- **D — 前端注入（复用）**：协议模板编辑/实例化页可经 `app/decorators` 注入「绑定 Item Template」面板与「自动带入库存项」提示，受现有权限门控。
- **E — 元数据/导出（复用）**：既有序列化器与导出 job（0011/0012）可直接序列化 Item Template 关联，无需另造导出通道。

## 四、设计决策（标注「待 /grill 确认」）

> 以下为分析与初步建议，**进入实施前须经 `/grill` 逼问确认**；结论补进 0016。

1. **范围 = 仅 T1（Item Templates 命名可复用抽象）**：核心**已实现**「协议挂库存项 + 实例化自动带入任务」（`protocol.rb:447-463`）；addon 仅补「命名 + 复用 + 可绑定多协议」的一等公民抽象，并可选加 `required` 强制标志；**不重写核心自动带入逻辑**。T2 为现有能力，不承接。
2. **数据模型（addon 自有迁移，不碰核心表）**：新增 `protocol_item_templates`（id / team_id / name / description / 关联 repository_template 或 repository_rows 集合），通过 `Extends` 合并注册，禁止改 `config/initializers/extends.rb` 本体；`protocol_repository_rows` 表本身**不新增列**（保持核心兼容），Item Template 与协议的绑定存于 addon 自有表，实例化时写入既有 `protocol_repository_rows`。
3. **实例化触发时机**：在协议被「链接到任务 / 从模板新建」时，addon 装饰该动作，按绑定的 Item Template 自动建立 `protocol_repository_rows`（复用 `protocol.rb:448-451` 拷贝语义）。
4. **最小 UI**：协议模板编辑页经 `app/decorators` 注入「Item Template 绑定」面板；协议实例化后在库存面板给出「已从模板带入 N 项」提示。**不重写核心库存/协议创建逻辑**。
5. **铁律守住**：全部改动收敛于 `addons/protocol_item_templates/`，绝不编辑核心 `app/`；扩展点走 `app/decorators` + `Extends` 合并 + 自有迁移。

> 注：本计划原拟用 0016，而 `docs/开发计划/官方功能/protocol-sop-management/实现现状与开发计划.md` 亦预留 0016（库协议版本通知）但**尚未落盘**至 `ARCHITECTURE_DECISIONS.md`（该文件当前止于 0015）。为避免序号冲突，本协议版本通知的 ADR 顺延为 **0017**；本 Templates 的 Item Templates 占用 **0016**。

## 五、PRD

**目标（In scope）**
- 提供一等公民的「物料模板（Item Template）」：**命名、可复用、可绑定到一个或多个协议模板（Protocol Template / SOP）** 的预选库存组合。注意官网 "Automatically prompt users..." 的**自动提示/带入已由核心 `ProtocolRepositoryRow`→`MyModuleRepositoryRow` 实现**，本 addon 不重复该能力，仅在核心之上叠加「可复用抽象 + 可选 `required` 强制标志」。
- 复用既有 `ProtocolRepositoryRow` 与 `RepositoryTemplate`，仅新增编排层与绑定关系。

**非目标（Out of scope，本期）**
- 不改核心 `app/`（铁律）。
- 不新增 `protocol_repository_rows` 表列（保持核心兼容）。
- 不实现底层库存数据模型（已由 `RepositoryTemplate` 覆盖）。
- 不新增角色/权限（复用既有协议与库存权限）。

**用户故事**
- 作为协议作者，我想为某 SOP 绑定一个「物料模板」（预选试剂/仪器/试剂盒），这样每次基于该 SOP 做实验时，所需库存项自动出现，避免漏选或选错批次。
- 作为 QA，我希望物料模板强制按批次/物料合规，减少批号不一致。

## 九、风险

- **核心钩子不确定性**：协议「实例化/链接到任务」动作的装饰点需 grill 时核实（用 `to_prepare` 装饰 `Protocol` 或 `protocols_controller` 相关动作）；二者均不碰核心本体。
- **与上游冲突**：上游未来若实现自有 Item Template，本 addon 的装饰/decorator 可能重复触发——覆盖点须在 rebase 时复核。
- **实例化语义依赖核心**：自动带入库存项完全依赖核心 `protocol_repository_rows` 拷贝语义（`protocol.rb:448-451`），addon 不得重写；核心行为变更时需回归。
- **范围边界**：T2（Forms 嵌入步骤的物料/字段联动）为现有能力，本期不承接，避免 scope 蔓延。
