一、SciNote 核心领域模型（host 实体）

实体内核：多租户 Team → Project → Experiment → MyModule(任务) → Protocol → Step；配方 Formulation 为 ai_eln addon 提供的一等实体，复用 RepositoryRow 物料主数据。

  • Team租户根 / 强约束 team_id
    • Usercreated_by 即此主键；持有 api_key / user_identities
    • Project一级容器
      • Experiment二级容器 · 网关核心写入目标
        • MyModule = 任务 / Task（API 路由名 tasks，模型名 MyModule，勿混淆）
          • Protocol → Step方法/步骤；Step 直接 belongs_to Protocol
          • UserMyModule任务成员 + assigned_by 指派者
          • Result / Asset结果 / 版本化附件
      • Repository → RepositoryRow库存表 / 物料行主数据
      • Report报告
    • Formulation 配方（PP 核心·ai_eln addon 一等实体）
      • FormulationComponentformulation + repository_row + amount + unit
      • FormulationPropertyname + measured/target + comparator + 可选 my_module_id
    • EquipmentBookingCalendarEvent 子类 · 设备预约
审计链约束（写入层设计基石）：API v1 的 experiments#create / tasks#create 均硬编码 created_by: current_user 且参数白名单不含该字段； addon 与宿主同进程，改以 Experiments::CreateService.call(user:, params) 直置 created_by —— 即记录永远落在真实绑定用户名下，网关无法伪造他人。

二、WechatGateway 集成层领域模型（addon）

① 双通道入口（已收敛）

iLink（私聊 DM，AES-128-ECB）：ilink_bridge / ilink_crypto / ilink_message_parser

企微自建应用（群聊+@+派任务，AES-256-CBC）：wecom_crypto / wecom_message_parser / wecom_controller

两通道归一为统一 Message(user_id, text, media, type, platform, raw, timestamp)，下游写入共用。

② 身份绑定（一次性绑定码，非 OAuth）

WechatUserBinding(wechat_id, platform, scinote_user_id) + 迁移 20260910120000

BindCode：8位 / 10分钟过期 / 生成时绑定 current_user（防冒领）/ 存 Rails.cache

BindingResolver：(wechat_id, platform) → scinote_user_id

③ 指令与草稿编排

Inbound.receive：解密→解析→身份解析→指令/写入链路

intake：指令路由 + 会话草稿（/new /use #id /done /cancel /confirm /list /search /admin /book）

SessionDraftStore：进程内 Hash（多 worker 并发风险）

④ 写入与 AI 加工

scinote_service_writer：Experiments::CreateService / append_note / assign_user / book_equipment / admin_experiments

ai_processor：多模态归一 + LLM 结构化抽取（components/results）

formulation_writer：写 Formulation/Component/Property（缺 material_resolver 致 component 全跳过）

出站回包链路断裂：所有回调控制器收到 reply 后仅 Rails.logger.info + head :ok，不回复发回用户。这是当前阻断端到端闭环的最大缺口（wecom_controller.rb:11-16、ilink_controller.rb:8-12）。

四、剩余缺口与优先级

[阻断] 出站回包 Sender 缺失

用户发 /new、/bind、/confirm 等指令后收不到任何回复，所有通道不可用。

修复：被动 XML 回复 / 企微客服消息 API / iLink 主动推送；见 docs/multi-channel-design.md §4

[阻断] BindController#confirm 损坏

调用不存在的 BindingResolver.confirm_by_code，访问即 500；且不建绑定行。

修复：补方法并接 create_binding，或删除该端点（聊天内 /bind 已是主流程）

[高] Formulation 成分落库为空

engine.rb:58 注入 FormulationWriter 未传 material_resolver，导致所有 component 被跳过，只有配方头 + property 写入。

修复：补"成分名→RepositoryRow"解析器并接线（PP 配方核心）

[高] 生成绑定码的宿主端点 / 设置页 UI

绑定码需由 current_user 在 SciNote 设置页生成；addon 内无铸码入口，/bind 流程无法自闭环。

修复：deface 注入"WechatGateway 绑定"面板调用 BindCode.generate

[高] 草稿存储并发风险

进程内 Hash 在多 worker / 多实例部署下草稿互相不可见，会丢用户工作态。

修复：换 Redis / DB 后端（SessionDraftStore 注释已承认）

[中] MyModule（任务）创建未实现

"派任务"目前仅为实验级成员指派，未创建独立任务实体；F6 完整语义待补 Tasks::CreateService。

[中] Result / 真实附件写入

媒体仅文本占位，未建 Result/Asset（ActiveStorage 挂接）。影响图片/文件证据留存。

[中] 企微 media_id 下载

仅 media_id 无 url 的企微图片/文件无法下载（media.rb 返回 nil）。

[待验证] iLink AES 推导 / 企微 @ 真机格式

ilink_crypto AES 推导、wecom_message_parser 群 @ 标记格式均为启发式，需真机/SDK 核对。

[中] 测试缺口

wecom_message_parser（@解析）、ilink_crypto、bind_code、各 controller、损坏的 bind#confirm 缺单测。

[中] /confirm 强锁 + 命名规范 naming

当前软锁非 SciNote 强锁；naming.rb 尚未移植，附件命名/校验缺位。

[低/增强] 语音 asr / user_identities 反向映射

Whisper 转写推后（Ticket 07）；微信 provider 反向映射推后（文档 A §3.3）。
