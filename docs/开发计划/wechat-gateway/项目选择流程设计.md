# 目标选择流程设计 —— /newexp 选 Project、/newtask 选 Experiment

> **本文分两篇**
> - **Part I**：`/newexp` 必须先选定 `Project` —— **已定稿 & 已实现**（2026-09-24）。
> - **Part II**：`/newtask` 必须先选定 `Experiment` —— **已定稿，待实现**（ADR 0028，ticket 19–22）。
>
> 两篇合起来是同一条通则：**显式 > 上下文 > 引导**（ADR 0028 §1）。

> 背景：SciNote 的实验（`Experiment`）**必须挂在某个项目（`Project`）下**，任务（`MyModule`）**必须挂在某个实验下**。
> 微信端只有一行文本输入框，没有「先选项目/实验弹窗」，所以任何创建指令前都必须先解决「放到哪个容器」。
> Part I 的实现代码在
> `addons/wechat_gateway/lib/scinote/wechat_gateway/{intake,user_state_store}.rb`
> 与 `app/models/scinote/wechat_gateway/user_state.rb`。

## 一、决策清单（9 问）

| # | 问题 | 结论 | 理由 / 影响 |
|---|---|---|---|
| Q1 | 如何引导 | **C 两阶段引导**：先列候选 → 用户回复编号 → 建实验 | 一阶段（预置默认项目直接建）在「项目多」时会静默放错地方；两阶段只多一次交互，且**选过即记住** |
| Q2 | 选过的项目是否记住 | **B 长期持久化**（DB，不是会话内） | 微信会话无状态；进程内 `SessionDraftStore` 重启即丢。持久化后普通路径零交互 |
| Q3 | 无预设时怎么办 | **C 自动列可建项目并等待编号**（不回落「随便一个默认」） | 回落默认 = 静默放错项目，比多问一句更贵 |
| Q4 | `/listproject` 列哪些 | **A 只列可建实验的项目**；`/listproject all` 看全部可读 | 列出来就是为了建实验，列不能建的是噪音；保留 `all` 供查找 |
| Q5 | `/setexp <实验>` 是否顺带切项目 | **A 是**，把该实验的所属项目设为默认 | 「切到这个实验继续干活」隐含「这个项目是当前上下文」 |
| Q6′ | 无预设时 `/newexp 标题 @日期` 的入参 | **A 暂存**进 pending，选完直接用，不重打 | 用户已经打过的内容不能丢 |
| Q7 | pending 歧义怎么判 | **A 只有「纯数字 + 落在候选内」才算选择**；其余取消 pending 并按普通消息处理；超时 **15 分钟**；候选最多列 **10 条** | 「3」可能是编号也可能是正文，但纯数字且命中候选的概率极高；其余一律不吞输入 |
| Q8 | 状态存哪 | **A 新建 `wechat_gateway_user_states` 表，主键 `scinote_user_id`**，含 `default_project_id + pending_*` | 绑定表唯一键是 `[wechat_id, platform]`（同一用户在 iLink/企微是两行），状态**不能**挂绑定行，否则换通道就丢；按 `scinote_user_id` 主键天然跨通道共享 |
| Q9 | 预设项目失效（权限被撤/已归档） | **A 每次 `/newexp` 前预校验**，失效即清空预设并重新引导 + 明确提示 | 否则用户会一直撞「无权限」错误而不知道要重选 |

> Q1(C) 与「Q3 回落默认」原本冲突；Q3 改判为 C 后冲突消解：**引导挂在 `/newexp` 上**，即
> 「没预设就问、问完记住、记住后不再问」。

## 二、状态机

```
          ┌──────────── /newexp [标题] [@起 ~止] ────────────┐
          │                                                  │
          ▼                                                  │
   resolve_default_project_id(user)                          │
          │                                                  │
    ┌─────┴─────┐                                            │
    │ 有预设 &  │  是 ──► 直接建实验（沿用标题/日期）──► 结束  │
    │ project_  │                                            │
    │ available │                                            │
    └─────┬─────┘                                            │
          │ 否（无预设 / 失效→清空并提示）                    │
          ▼                                                  │
   start_project_selection                                   │
     · 列 ≤10 个可建实验的项目（#id 名称）                     │
     · pending = { candidates:[ids], title, start, due, note }│
     · TTL 15min                                             │
          │                                                  │
          ▼                                                  │
   等待下一条消息 ──► 纯数字 & 在候选内 ──► 建实验（沿用暂存） │
        │                                  + 记住该项目 ──────┘
        ├──► "0" ──────────► 取消，不建任何记录
        ├──► 其它（含命令）─► 取消 pending，按普通消息/命令处理（内容不吞）
        └──► 超时 15min ───► pending 视为不存在，下次 /newexp 重新引导
```

**普通文本录入**（非指令）同样适用：无当前草稿且无可用默认项目 → 引导选项目，
并把**本条文本暂存**为 `note`，选完自动写进新实验正文（不丢内容）。

## 三、数据模型

`db/migrate/20260924120000_create_wechat_gateway_user_states.rb`

| 列 | 类型 | 说明 |
|---|---|---|
| `scinote_user_id` | bigint **PK** | 跨通道共享（iLink 与企业微信同一用户 = 同一行） |

- 长期状态 → `UserStateStore`（DB，跨消息/跨进程/跨通道）
- 当前草稿 → `SessionDraftStore`（内存 Hash，见已知限制）

## 五、关键实现注意点

1. **无权限要提前拦**：`CreateExperimentService` 无权时返回 `nil`（`ActiveRecord::Rollback`），
   直接 `exp.id` 会 `NoMethodError` 冒泡成 500。已在 writer 里用
   `can_create_project_experiments?` 前置校验并抛中文错误。
2. **pending 不能吞输入**：非选择消息一律取消 pending 后**继续走原逻辑**，
   由 `with_notices` 在回复前附加一行「已取消上一条…」提示。
3. **pending 优先级最高**：`handle` 里在 `route_command` 之前拦截，
   否则 `/setexp 12` 这类消息会被当成命令而忽略待选状态。
4. **不要依赖 `WECHAT_GATEWAY_PROJECT_ID`**：它现在只是「无用户级预设时的实例级回落」，
   `/newproject` 等需要 team 的动作改走 `resolve_team`（默认项目 team → 用户第一个 team），
   新用户未配置也能用。

# Part II — `/newtask` 必须先选定 Experiment（已定稿，待实现）

> 设计文档：`docs/adr/0028-wechat-gateway-target-selection.md`
> 实现 ticket：`.scratch/wechat-gateway/issues/{19,20,21,22}-*.md`
> **本部分截至 2026-09-24 尚未动一行代码**；`/newtask` 当前仍是「行内传实验 ID」的旧语法。

SciNote 里 `MyModule`（任务）挂在 `Experiment` 下，`Experiment` 挂在 `Project` 下。
`/newtask` 因此比 `/newexp` **深一层容器**：不但要知道项目，还要知道项目里的哪一个实验。

## 7.1 决策清单（8 问）

| # | 问题 | 结论 | 理由 / 影响 |
|---|---|---|---|
| Q1 | `/newtask` 的目标实验怎么定 | **A 对称于 `/newexp`**：目标 = **当前实验**，没有才引导；不支持行内 ID | 「首位数字即 ID」的猜测与待选态「纯数字 = 选编号」规则撞车；代价是 `/newtask <实验ID> …` 成为**破坏性语法变更** |
| Q2 | 引导是自适应还是固定两级 | **A 自适应**：默认项目已记住 → 只列实验（一级）；否则项目 → 实验（两级） | 项目长期记住的前提下，多数情况只需选实验；为一致性多问一次不划算 |
| Q3 | 实验候选资格 | **A 只列「可建任务」的实验**（可读 + 未归档 + `can_create_experiment_tasks?`） | 与「`/listproject` 只列可建实验的项目」同一条原则：列出来的就是要建的 |
| Q4 | 选中的实验要不要长期记住 | **B 长期持久化**（新增 `default_experiment_id`）⚠️ 偏离了推荐 A | 短期态多 worker/重启即丢，用户回来又得重选；代价由 §7.4 四条派生决定买单 |
| Q5 | 待选结构怎么扩 | **A `pending_action` 加取值 `select_experiment`**，payload 带 `project_id`；**两级 = 串联两次单步**，不是队列 | 与现有 schema 兼容；通用步骤队列对「最深两级」是过度设计 |
| Q6 | 两级时选完项目是否顺手记住 | **A 记住**（与 `/newexp`、`/setexp`、`/newproject` 一致） | 用户挑的那个项目本来就是他要在里面干活的项目 |
| Q7 | 该项目下一个实验都没有时 | **A 明确提示 + 给下一步**（`/newexp` 先建 或 `/listproject` 换一个） | 「自动代建实验」会让用户去 Web 端找一个自己不认识的 `微信记录-<uid>` 容器，而网关按 ADR 0027 不提供删除 |
| Q8 | 术语表要不要泛化「待选项目」 | **A 泛化为「待选（pending）」**，`select_project` 降级为其一例 | 机制可复用，后续多级引导不必再造词 |

## 7.2 状态机

```
                    /newtask [任务名] [~截止]
                              │
                              ▼
            ① 当前实验存在？（SessionDraftStore 短期索引）
                 是 ──────────────────────────────────────────┐
                 否                                            │
                              ▼                                │
            ② 默认实验有效？（可见 + 未归档 + 可建任务）         │
                 是 ──► 恢复为当前实验 + 回复明示 ──────────────┤
                 否（清空并提示）                               │
                              ▼                                │
            ③ 默认项目有效？（存在 + 未归档 + 可建实验）         │
                 是 ──► 一级引导：列 ≤10 个可建任务的实验        │
                 否 ──► 两级引导：先列可建实验的项目             │
                          │                                    │
                          │  ← 选编号                           │
                          ▼                                    │
                   记住该项目为默认项目（顺手）                  │
                          │                                    │
                          ▼                                    │
                   列该项目下可建任务的实验（≤10）               │
                          │                                    │
                          │  ← 选编号                           │
                          ▼                                    │
               写入默认实验（长期记住）◄────────────────────┘
                          │
                          ▼
        CreateMyModuleService 建任务 ──► 当前草稿切到该实验
                                        （= 默认实验，二者同源）
```

**待选交互规则沿用 Part I**（不重写一套）：

| 输入 | 行为 |
|---|---|
| 纯数字 **且** 落在候选编号内 | 视为选择，消费 pending 并进入下一步 |
| `0` | 取消，不建任何记录 |
| 其它（含其它指令） | **取消 pending，按原逻辑处理**（内容绝不吞），回复附一行「已取消上一条等待」 |
| 超时 **15 分钟** | pending 视为不存在，下次重新引导 |
| 同一会话重复触发且仍无可用目标 | 降级为一次性「先 `/setproject`」指引，**不死循环** |

## 7.4 Q4 = B 的四条派生决定（把「两个真值来源」收敛掉）

直接加一列而不作约束，会造出「当前实验」的两个可以各说各话的来源（术语表 §10 已为此类混用立过禁令）。
因此同时规定：

| # | 决定 | 理由 |
|---|---|---|
| **D1** | **短期索引 = 长期值的缓存**。二者不是两个概念，只是两种寿命；由**唯一解析入口**对齐（先读内存，落空则从 DB 恢复并写回） | 否则会出现「内存说 #12、DB 说 #30」的分裂 |
| **D2** | **恢复前必须重新校验**：可见性 + 未归档 + 对应写权限（ADR 0025）；失效即清空 + 提示，**不静默回落** | 实验比项目更容易过期（收尾 / 归档 / 撤权），拿过期 ID 恢复等于替用户选了一个他早已离开的位置 |
| **D3** | **`/cancel` 同时清短期索引与长期默认实验** | 否则「取消」会被下一条消息立刻撤销，用户被困在同一实验里 |
| **D4** | **`/setexp <实验ID>` 同步设为默认实验**（含原有的「切草稿 + 设默认项目」） | 否则 `/setexp` 的效果在重启后只剩一半 |

> 四条均可低成本逆转；它们不是新的设计问题，而是 Q4=B 的必要配套。

## 7.6 关键实现注意点

1. **先过闸，再开门**：实验候选过滤依赖 `can_create_experiment_tasks?`（ticket 13）与可见性基座（ticket 11）。
   在闸门之前开放引导，等于把一份「你可建任务的实验清单」交给一个尚无写权限校验的写入层。
2. **无权限要提前拦**：`CreateMyModuleService` 无权时与 `CreateExperimentService` 同作派 —— 返回 `nil`，
   直接取 `id` 会炸 `NoMethodError`；必须前置权限拦截。
3. **MyModule 没有 `start_date`**：只支持 `~截止`，提供的 `@起始` 忽略（Part I 已确认）。
4. **候选上限 10 条**，超出时提示收窄（`/listproject` / `/listexp`）而不是截断后让用户猜。
5. **每条候选必须带编号 + 团队标注**（ADR 0026 呈现要求）。
