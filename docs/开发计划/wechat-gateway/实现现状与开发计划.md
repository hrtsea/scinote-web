## 1. 目标与范围（来自 WECHAT-SCINOTE-PLAN §3）

### 1.1 目标
把微信群 / 企微群 / 私聊里的实验记录自动落到 SciNote，支持「组长派任务给组员」，落库作者必须是真实操作人（审计链正确），正式签署/计量/批次仍走 Web 端。

### 1.2 功能清单（F1–F10）
| 编号 | 功能 | addon 方案 | 状态 |
|---|---|---|---|
| F1 | 私聊 @bot 获取微信身份 | iLink DM | ✅ 桥接完成 |
| F2 | 群聊 @bot 获取微信身份 | 企业微信自建应用 | ✅ 桥接完成 |
| F3 | 微信↔SciNote 用户映射 | `wechat_user_bindings`（不存 token） | ✅ 完成 |
| F4 | 以用户名义建实验 | `Experiments::CreateService.call(user:, ...)` 置 `created_by` | ❌ 写入层待实现 |
| F5 | 文本/图片/文件/语音落库 | Ruby 化 intake（正文追加/附件/视觉识别） | ❌ 写入层待实现 |
| F6 | 组长指派任务给组员 | 校验 `can_manage_my_module_users?` 后调指派 service | ❌ 待实现 |
| F7 | 指令系统 | `/new` `/use` `#` `/done` `/cancel` 等 Ruby 化 | ❌ 写入层待实现 |
| F8 | 身份绑定引导 | 一次性绑定码（`/bind <码>`） | ⚠️ 码/指令已建，未在 inbound 触发 |
| F9 | 管理员查询用户实验/任务 | addon 内管理员上下文直查 | ❌ 待实现 |
| F10 | 设备预约 | addon 内直用 `EquipmentBooking` | ❌ 待实现 |

### 1.3 非范围（明确不做）
- 不修改 experiments/tasks 等 host 表结构（仅以真实用户经 service 写入）。

- 语音 asr / AI 结构化抽取为增强阶段（v1：文本保真 + 图片视觉识别）。

## 2. 架构决策（摘要，详见 ADR 0023）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 进程内 Rails Engine addon（非独立 Python 网关） | 免逐用户 OAuth token；直调 service 置 `created_by` |
| D2 | 双通道统一收敛（iLink + 企微） | 下游写入逻辑共用，入口仅负责取身份+收消息 |
| D3 | 一次性绑定码（非 OAuth） | 绑定只需确认「微信=该 SciNote 用户」，进程内安全 |
| D4 | 写库作者=真实用户（`user:` 参数） | GLP 审计链正确，不挂名 bot |
| D5 | 零侵入注册（Gemfile 一行 + engine 自挂载） | 遵循 ADR 0022 统一机制，卸载零改动 |
| D6 | 草稿 + `/confirm` 两阶段 | 先建草稿，本人确认才锁定，降低误录 |
| D7 | AI 视觉/语音失败降级为原文保真 | 不阻塞录入，关键数值 Web 端复核 |

## 4. 数据模型（引擎自有表，D5）

```ruby

create_table :wechat_user_bindings do |t|
  t.string :wechat_id,        null: false   # 微信/企微 userid
  t.string :platform,         null: false   # 'ilink' | 'wecom'
```

## 6. 桥接层（D2，已完成）

- **企微 `wecom_crypto.rb`**：`verify_url(params)`（GET 校验原样返回 `echostr`）、`decrypt_callback(raw, params)` / `decrypt(raw, params)`（AESKey=base64decode(EncodingAESKey+"=")，AES-256-CBC，PKCS7 去填充，明文=random(16)+msg_len(4 大端)+msg+receiveid）。验签 `sha1(sort([token,timestamp,nonce,encrypt]))`。
- **企微 `wecom_message_parser.rb`**：解析 XML → `Message`（`FromUserName`=成员 userid；群聊带 `ChatId`；当前私聊已解析，群 @ 解析待增强见 §12）。
- **iLink `ilink_crypto.rb` / `ilink_message_parser.rb`**：AES-128-ECB 解密 + 长轮询消息解析为 `Message`（私聊 DM）。

## 12. 企业微信接入技术要点（wecom_bridge Ruby 实现参考，来自 plan §9）

- **凭证**：`corpid` / `corpsecret` / `agentid` 在企微后台「应用管理→自建」获取；`access_token` `GET qyapi.weixin.qq.com/cgi-bin/gettoken`（7200s 过期，需缓存）；收消息**不需要** token，主动调 API（下载媒体/被动回复）才需要。
- **回调验签 + AES 解密**：GET 校验（`msg_signature/timestamp/nonce/echostr`）；POST Body 为 XML（`<Encrypt>` 包裹）。`msg_signature=sha1(sort([token,timestamp,nonce,encrypt]))`；`AESKey=base64decode(EncodingAESKey+"=")`（32 字节），`IV=AESKey[:16]`，AES-256-CBC，PKCS7 去填充。
- **私聊 vs 群聊 + @**：私聊无 `ChatId`，`FromUserName` 即成员；群聊带 `ChatId`，`Content` 含 @信息（企微群 @ 文本内嵌 `\u0001@userid\u0001` 风格，以真实回调核对）。
- **媒体下载**：图片/文件/语音带 `MediaId` → `GET qyapi.weixin.qq.com/cgi-bin/media/get?access_token=TOKEN&media_id=ID`。
- **与 iLink 差异**：收消息（长轮询 vs HTTPS webhook）、群事件（平台不投递 vs 官方支持）、加解密（AES-128-ECB vs AES-256-CBC）、身份（openid/昵称 vs 稳定 userid）。
