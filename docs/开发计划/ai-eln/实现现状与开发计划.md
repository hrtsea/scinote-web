> 文档版本：V1.0（规划） ｜ 面向 SciNote 二次开发，零侵入 addon 方案
> 关联：需求规格 `AI-ELN 需求规格文档 V1.0`、领域术语 `docs/开发计划/ai-eln/CONTEXT.md`、架构决策 `docs/ARCHITECTURE_DECISIONS.md` 0001
> 适用：材料/高分子配方研发、自托管 SciNote 开源版、GLP 溯源约束、AI 仅作辅助、不替代原始记录

## 0. 承重事实（已与代码库核对，非假设）

1. **addon 零侵入范式已验证**：引擎 `engine.rb` 用 `initializer` 自注册 `mount Scinote::AiEln::Engine => '/'`，host `config/routes.rb` 零改动；Gemfile 注释该 gem 即整体禁用，Rails 正常启动。
2. **既有 `ai_protocols` addon**：已实现「自由文本/PDF → 规程模板」（`ProtocolGenerator` + `LlmClient`），对应 spec 的 AI-201 / AI-101 子集。其 LLM 客户端在 `lib/scinote/ai_protocols/llm_client.rb`：
   - 接口 `LlmClient.new(base_url:, api_key:, model:)` + `#chat_with_schema(system_prompt:, user_prompt:, schema:, schema_name:)`；
   - 网络调用集中在私有 `#post`，spec 可直接 stub；
   - 仅支持 OpenAI 兼容协议——**Ollama 的 `/v1/chat/completions` 同协议，故天然兼容本地私有化部署**。
3. **特性开关范式（沿用）**：`ai_protocol_parser_enabled`（DB，`EnableFeatureFlags` 迁移写入）**且** `AI_PROTOCOLS_PARSER`（ENV）。本插件用 `ai_eln_enabled` + `AI_ELN_PARSER`。
4. **引擎自有表迁移**：官方脚手架 `lib/generators/addon/templates/engine.rb` 含 `append_migrations` initializer，将 `addons/ai_eln/db/migrate` 追加进 host 迁移路径。**宿主 `db/migrate` 不改动**（esignatures 那次直接塞宿主属特例，本插件走标准模式）。
5. **权限接入**：canaid 自动扫描 addon `app/permissions`；视图注入两条现成路径：`app/overrides`（deface，如 ai_protocols）+ `app/decorators`（手动加载，如 project_insights）。
6. **webpacker 接线**：addon 的 JS pack 必须在 `config/webpack/webpack.config.js` 的 `entryList` 手动加一行（已踩坑，非业务 app/）。
7. **测试环境陷阱**（实测）：`create(:user)` 因 `Rails.configuration.x.enable_email_confirmations` 恒 truthy 触发确认邮件失败；须在 `before(:all)` 重写 `User#send_devise_notification` 为空操作。view spec 隔离上下文下引擎路由 helper 不可用，需 `view.extend(Scinote::AiEln::Engine.routes.url_helpers)`。test 环境 webpacker manifest 缺失，不能写「请求 dashboard」类 spec 测 JS tag。

## 1. 目标与范围

### 1.1 目标
不改动 SciNote 核心，以独立 Rails Engine 注入全部 AI 增强能力（实验辅助、文档/图谱解析、配方智能处理、语义检索、GLP 合规自检、多语言），兼容原有业务、权限、审计追踪、电子签名、导出。

### 1.2 范围（来自 spec §2，25 功能）
| 模块 | 功能 |
|---|---|
| 实验记录 AI 辅助 | AI-001 方案生成 / AI-002 润色 / AI-003 自动小结 / AI-004 失败根因分析 |
| 文档与图谱解析 | AI-101 PDF 解析 / AI-102 图片OCR+草稿 / AI-103 CSV 解析 |
| 配方智能处理 | AI-201 文本解析配方 / AI-202 配比校验 / AI-203 历史参数建议 |
| 智能检索 | AI-301 语义检索 / AI-302 相似实验推荐 / AI-303 异常数据提示 |
| 合规与多语言 | AI-401 GLP 自检 / AI-402 翻译 / AI-403 审计日志导出 |

### 1.3 非范围（明确不做）
- 不修改 experiments/recipes/samples 等 host 表结构；AI 输出只关联、不覆盖。
- 不改造原表单存储、样本、库存、任务业务。
- 向量数据库（spec §8.1）暂不做；AI-301/302 的 v1 用「LLM 重排 + host 现有搜索」实现，非语义向量召回。
- 贝叶斯配方优化闭环（原 §8.2）**调整为纳入范围**，见新增 §12（纯 ruby 轻量 GP 后端，单目标/无约束优先，多目标为已知限制）；仪器自动上传、AI 生成 PPT 仍留作后续。

## 2. 架构决策（摘要，详见 0001）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 新建独立 `ai_eln` 引擎，与 `ai_protocols` 并列共存；ai_eln 自带独立 `LlmAdapter`（Ollama/OpenAI 双后端），**不**复用 ai_protocols 的 `LlmClient` | 边界清晰、可独立启停；不合并避免与已上线协议生成耦合 |
| D2 | 首切片 = 地基（骨架+开关+适配层+三表+审计+抽屉外壳） | 25 功能共用地基，避免每功能重复搭 |
| D3 | 配置用 ENV + `ApplicationSettings#values` 特性开关 | 与现有 addon 一致，可热切换、不改代码关 AI |
| D4 | 引擎自有表走 `append_migrations` | 宿主 `db/migrate` 零改动，满足零侵入 |
| D5 | 视图注入用 deface `app/overrides` + `app/decorators` | 沿用两条已验证路径 |
| D6 | AI 输出一律 HITL：预览 + 显式确认，禁止自动写 host 记录 | GLP 合规，原始记录不可篡改 |
| D7 | 审计写入与业务解耦：每次调用落 `ai_audit_logs` | 合规可导出，且不阻塞主流程 |

## 4. 数据模型（引擎三表，D4）

```ruby
create_table :ai_eln_ai_sessions do |t|
  t.references :user, null: false, foreign_key: true
  t.string     :context_type          # 'Experiment' / 'Protocol' / 'Project' / 'Note'
  t.bigint     :context_id
  t.string     :title
  t.timestamps
end

create_table :ai_eln_ai_interactions do |t|
  t.references :ai_session, null: false, foreign_key: { to_table: :ai_eln_ai_sessions }
  t.text       :prompt
  t.text       :response
  t.string     :model_name
  t.integer    :prompt_tokens
  t.integer    :completion_tokens
  t.string     :status, default: 'success'   # success / failed
  t.text       :error
  t.timestamps
end

create_table :ai_eln_ai_audit_logs do |t|
  t.references :user, null: false, foreign_key: true
  t.string     :feature_id            # 'AI-101' ...
  t.text       :input
  t.text       :output
  t.string     :model_name
  t.timestamps
  t.index       [:feature_id, :created_at]
end
```
> 表名前缀 `ai_eln_` 避免与 host/其他 addon 冲突。关联用 polymorphic `context_type/context_id`，不新增 host 外键。

## 5. 配置与开关（D3）

- `ai_eln_enabled`（DB，`ApplicationSettings#values`）：由迁移置 `true`（默认全关，需开启）。
- `AI_ELN_PARSER`（ENV）：LLM base URL，如 `http://127.0.0.1:11434/v1`（Ollama）或 OpenAI 兼容地址。缺失即视为关闭。
- `AI_ELN_API_KEY`（ENV，可选）：自托管可空。
- `AI_ELN_MODEL`（ENV，默认 `qwen2.5-14b-instruct`）。
- 判定方法 `Scinote::AiEln.enabled?` = `ApplicationSettings.instance.values['ai_eln_enabled'] && ENV['AI_ELN_PARSER'].present?`
- 关闭时：`Scinote::AiEln.enabled?` 为 false → deface override 不渲染抽屉、`application_controller` before_action `render_403`，整体退化为原生 SciNote。

## 6. LLM 适配层（D1，ai_eln 自有，不复用 ai_protocols）

`Scinote::AiEln::LlmAdapter`（位于 `app/services/scinote/ai_eln/llm_adapter.rb`）：
- `complete(prompt:, model:, max_token:)` → 按 `Scinote::AiEln.configuration.llm_backend` 在 `ollama` / `openai_compatible` 间切换，直接 `Net::HTTP` 调 `chat/completions`。
- 后端选择：`ollama`（私有化优先，请求不离开内网，防配方泄露）/ `openai_compatible`（含 Azure OpenAI）；两者均走 OpenAI 兼容协议。
- 失败统一抛 `Scinote::AiEln::LlmAdapter::ApiError`，由调用方记 `ai_audit_logs` + 返回用户友好错误。
- **耦合说明（已核实）**：ai_eln 的 `LlmAdapter` 为**自有实现**，不引用 `Scinote::AiProtocols::LlmClient`；与 ai_protocols 是各自独立挂载、互不耦合的姊妹 addon，任一可被单独禁用而互不影响。

## 7. 侧边抽屉 UI 与权限（D5/D6）

- 注入点（deface `app/overrides/ai_eln_drawer.rb`）：在 `experiments/show`、`protocols/show`、`my_modules` 头部注入「AI 助手」按钮 + 渲染 `ai_eln/_drawer` partial。
- 条件渲染：`enabled?` 为假 或 `can_use_ai_eln?(current_user, current_team)` 为假（只读角色）→ 不渲染任何 AI UI。
- 抽屉内：每个功能一个面板（后续 Issue 填充），统一「输入 → AI 生成 → 预览 → 用户确认 → 落附件/关联表」流；**绝不自动写 host 记录**。
- JS：`ai_eln_drawer.js` 经 `javascript_include_tag 'ai_eln_drawer'` 注入（参照 project_insights 的 decorator 注入机制，避免 view spec manifest 缺失）。

## 9. Issue 拆分（垂直切片，tracer bullet）

> 规则：每 Issue 端到端贯通 schema→service→controller→UI→spec，独立完成可验证。P1 为地基，P2–P17 为功能切片，均依赖 P1。

### P1 — 引擎骨架 + 开关 + LLM 适配 + 三表 + 审计 + 抽屉外壳【地基，可立即开始】
- 范围：§3 目录、`engine.rb`（自注册路由 + `append_migrations` + 加载 overrides/decorators）、§4 三表迁移、`LlmAdapter`、`AuditLogger`、`can_use_ai_eln?` 权限、deface 在 experiments/show 注入抽屉外壳（只读隐藏、关闭不渲染）、i18n 骨架、Gemfile/webpacker/.env 接线、迁移写 `ai_eln_enabled`。
- 验收：`Scinote::AiEln.enabled?` 双判定正确；drawer 在 experiments/show 出现且只读角色不可见；关闭后整引擎零 UI 零路由副作用；三表迁移 `rake db:migrate` 成功且宿主 `db/migrate` 未新增；`LlmAdapter` spec stub `LlmClient` 验证转发；审计写入有 model spec。
- 依赖：无。

### P2 — AI-101 附件 PDF 解析（文本/表格提取 + 导入笔记预览）
- 范围：上传 PDF → `pdftotext`（复用 host poppler）提取文本/表格 → LLM 结构化 → 预览 → 用户确认后作为笔记附件/文本填入。>10MB 走 Sidekiq 异步（复用 host 队列，非功能需求 §3.1）。
- 验收：多页 PDF 提取；预览可编辑；确认后才落 host 笔记；异步任务有 job spec。
- 依赖：P1。同时为 P3/P9 提供「附件文本提取」共享能力。

### P3 — AI-102 图片 OCR + 实验草稿解析
- 范围：手写笔记/图谱截图上传 → OCR（tesseract 或 LLM 多模态，待定）→ LLM 区分样品编号/配方配比/测试数据/现象 → 预览 → 用户确认填入。
- 验收：OCR 结果 + 结构化预览；禁止自动写原始记录。
- 依赖：P1。（OCR 引擎选型为待确认决策，见 §10）

### P4 — AI-103 仪器 CSV 数据解析
- 范围：设备 CSV → 解析关键指标 → 预览表格 → 用户确认复制使用。
- 依赖：P1。

### P5 — AI-001 实验方案生成
- 范围：输入目标/物料/约束 → LLM 生成步骤/预期现象/风险提示 → 存附件，用户手动复制。
- 依赖：P1。

### P6 — AI-002 文本规范化润色
- 范围：选中笔记文本 → 规范化 → 原文本不变，润色版作附件。
- 依赖：P1。

### P7 — AI-003 实验自动小结
- 范围：选定实验 → 聚合本实验全部字段+附件 → LLM 小结 → 周报草稿。
- 依赖：P1。（聚合读取 host 实验字段，只读）

### P8 — AI-004 失败现象根因分析
- 范围：填失败现象 → 检索本项目历史实验 → LLM 给潜在根因清单（仅参考）。
- 依赖：P1。

### P9 — AI-201 非结构化文本解析配方
- 范围：粘贴自由文本配方 → LLM 提取组分/质量体积/摩尔占比 → 方向 X 表达预览（映射为「基准模板内挂接 RepositoryRow + `stock_consumption` 质量份」）→ 确认后写入克隆实验的挂接行（HITL，不自动建配方实体）。
- 依赖：P1、P2（文本提取可复用）。

### P10 — AI-202 配方配比校验
- 范围：读现有配方 → 提示配比总和异常/单位冲突（仅提示，不改数据）。
- 依赖：P1。

### P11 — AI-203 历史实验参数建议
- 范围：读当前项目已完成实验 → LLM 给下一组候选配方参数 → 候选表单预览（方向 X：表格呈现，人工粘贴到克隆基准模板）→ 确认后克隆基准模板新建实验。
- 依赖：P1。

### P12 — AI-301 语义自然语言检索
- 范围：自然语言查询 → 对实验笔记/附件文本 LLM 重排 → 返回相似实验（v1 基于 host 现有搜索 + LLM 重排，非向量库）。
- 依赖：P1。（向量库为后续 §8.1）

### P13 — AI-302 相似实验案例推荐
- 范围：新建实验时自动检索本项目历史相似实验，展示过往条件/失败案例。
- 依赖：P1、P12（复用重排）。

### P14 — AI-303 异常数据提示
- 范围：对比同批次历史数据集 → 标记当前指标偏离区间 → 人工复核确认。
- 依赖：P1。

### P15 — AI-401 GLP 记录自检
- 范围：扫描当前实验记录 → 提示缺失元数据（试剂批号/设备编号/环境条件）→ 自检报告附件。
- 依赖：P1。

### P16 — AI-402 记录内容翻译
- 范围：选中笔记文本 → LLM 动态翻译（区别于 host 静态 yml）。
- 依赖：P1。

### P17 — AI-403 AI 调用全审计日志（查看 + 管理员导出）
- 范围：基于 P1 的 `ai_audit_logs` → 管理员页面查看 + CSV/JSON 导出。
- 依赖：P1。

## 10. 待确认决策（实现前需拍板）

## 12. 贝叶斯配方优化模块（原 §8.2 闭环，新增 AI-501）

### 12.1 模块定位与边界
- **功能 ID：AI-501 贝叶斯配方优化（候选生成）**。从已完成任务中自主学习「配方 + 工艺 → 性能指标」映射，给出下一组高潜力候选配方。
- **纯辅助**：候选为 draft，绝不自动扣库存、绝不自动写原始记录（复用 D6 HITL）。
- **本模块不调用 LLM**（纯数值优化），但与 `LlmAdapter` 同引擎；审计照常落 `ai_audit_logs`。
- **后端**：纯 ruby（无 python 依赖）。◆ 能力限制见 §12.6。

### 12.2 配方数据模型约定（方向 X：鹰谷-lite，无配方实体表）【已锁定：用户 2026-09-03 选 X】
本次 grill 锁定（Q1/Q2/Q3）+ 配方表达决策：
- 性能指标 ← my_module 下 ResultTable 命名列（按列名匹配）【Q1 确认】
- 工艺参数 ← 同 ResultTable 列（与指标同源）【Q2 确认】
- 计算后端 ← 纯 ruby 轻量实现【Q3 确认】
- 配方表达 ← 方向 X（鹰谷-lite）：不建配方实体表；基准配方 = 实验模板、实验配方 = 克隆实验内挂接 RepositoryRow、工艺/性能 = ResultTable【用户 2026-09-03 选定】

**配方在本仓的真实表达（方向 X）：**
- 基准配方（BaseRecipe）= SciNote 实验模板（`CopyExperimentAsTemplateService`）；模板内挂接的 RepositoryRow 即固定+变量组分；溯源靠模板名/备注（鹰谷式，无自动父子链，GLP 靠模板命名规范补强）。
- 实验配方（ExperimentRecipe）= 从基准模板克隆的实验；组分 = 该 my_module 经 `MyModuleRepositoryRow` 挂接的 RepositoryRow，其 `stock_consumption` = 该组分投料质量份；模板态不填 consumption 即不扣库存。
- 组分身份 = 挂接的 RepositoryRow（物料）；质量份 = `MyModuleRepositoryRow#stock_consumption`（数值）。
- 工艺 / 性能 = `ResultTable` 命名列（已锁 Q1/Q2）。

**贝叶斯变量 / 固定区分（轻量优化配置，非配方实体）：**
- 不引入 recipe/component/version 表；变量标记 + 上下界以「优化配置」承载：per 基准模板记录哪些挂接行名 = 变量组分（`is_variable`）+ 其上下界，固定组分从模板继承。
- 配置载体：引擎小表 `ai_eln_recipe_opt_config`（`base_template` 标识 + 组分名 + `is_variable` + `lower` + `upper`），仅贝叶斯读取，不侵入 host、不构成配方管理域（D4 `append_migrations`）。

**可配置项**（`ApplicationSettings#values`，沿用 D3）：
- `ai_eln.base_template_selector`：识别基准模板的方式（名称前缀 / 标签 / id）
- `ai_eln.component_row_selector`：识别「组分」挂接行的方式（物料库 Repository 名 / 行名前缀）
- `ai_eln.metrics_column_map`：`{ 指标名 => ResultTable 列名 }`
- `ai_eln.process_column_map`：`{ 工艺参数名 => ResultTable 列名 }`
- `ai_eln.candidate_output`：方向 X 固定为 `:table_preview`（候选表格预览 + 人工粘贴到克隆模板，不自动建实验、不写 stock）

若后续改用方向 Y（建配方引擎表），仅新增对应 `RecipeAdapter` 子类并改配置，`DatasetExtractor` 核心不变（统一接口 `#each_sample(scope) → Enumerator<Sample>`）。

### 12.3 数据集抽取层（DatasetExtractor + RecipeAdapter）
- `RecipeAdapter`（抽象）：`samples(scope) → [{ x: Vector, y: Hash<metric,Float>, meta: {...} }]`，从 scope（project / team / 指定 my_modules）拉 `completed` my_module 组装。
- 默认 `RecipeRepositoryAdapter` 按 §12.2 配置实现。
- 容错：列不存在 / 空值 → 跳过该样本并记 service warning（不落 audit）。
- 归一化：组分质量份 / 工艺参数按各自定义域（配置 min/max 或自动从样本估计）归一，供 GP 使用；候选产出时反归一回真实单位。

### 12.4 贝叶斯后端（BayesianOptimizer，纯 ruby）
- **默认数值后端**：`Numo::NArray`（纯 ruby，无 python）做矩阵运算；GP 核心自实现（RBF/Matern 核 + Cholesky 求解 + 边际似然超参点搜索）。若要求零 gem，可降级纯 Ruby Array 实现（更慢、精度略降）。
- **采集函数**：EI（Expected Improvement）/ UCB（Upper Confidence Bound），单目标。
- **优化**：在参数空间（组分 + 工艺的归一域）上网格 / 随机 + 轻量局部搜索最大化采集 → top-k 候选。
- **多目标 / 约束**：◆ 见 §12.6 限制；v1 提供加权标量化（scalarized EI）作多目标近似，约束以「可行性惩罚」处理（弱）。
- 接口：`BayesianOptimizer.fit(x:, y:) → model`；`model.suggest(k:, bounds:) → [candidate_vectors]`；`model.evaluate(x) → { mean, std }`。
- 失败：样本不足（< ~8 条）抛 `InsufficientData`，UI 提示「需更多已完成实验」。

### 12.5 候选产出与 HITL（AI-501 wizard）
- 流程：抽屉面板「贝叶斯优化」→ 选目标指标 + 可选约束（指标上下界 / 工艺范围）+ 样本范围（基准模板）→ `DatasetExtractor` → `fit` → `suggest(top-k)` → **方向 X：候选以表格预览呈现**（组分质量份 + 工艺参数，标注预测均值 ± 方差），**不自动建实验、不写 stock**；用户确认后**人工粘贴到从基准模板克隆的实验**（HITL）→ 写 `ai_audit_logs`（feature_id=AI-501）。
- **关键不变量**：候选仅为预览表格，绝不进入 `MyModuleRepositoryRow` / stock 关联路径、绝不自动建 my_module，故不扣库存。验证：spec 断言 `deduct_stock_balance` 回调未被触发、无新建 my_module。

### 12.6 已知限制（写进计划，不阻塞）
1. 纯 ruby GP 对**多目标**与**硬约束**支持弱：v1 仅单目标稳健；多目标用加权标量化近似，约束用可行性惩罚（非严格可行），质量依赖权重设定。
2. 样本量门槛 ~8–15 条 `completed` my_module 才有意义；少于则 EI 退化。
3. `Numo` 为新增 gem 依赖（纯 ruby，无 python）；零 gem 降级见 §12.4。
4. 配方映射已定为方向 X（实验模板 + `MyModuleRepositoryRow` + `ResultTable`），无配方实体表；变量/固定区分经轻量「优化配置」`ai_eln_recipe_opt_config`，见 §12.2。

### 12.7 Issue 拆分（AI-501 垂直切片）
- **P18 — 数据集抽取层（RecipeAdapter + DatasetExtractor）**：配置驱动的抽取；model/service spec（factory 造 RepositoryRow + ResultTable + MyModuleRepositoryRow）；列缺失容错 spec。依赖 P1。
- **P19 — 纯 ruby 贝叶斯后端（BayesianOptimizer）**：GP + EI/UCB + suggest；纯数值 spec（在已知解析函数上验证 EI 收敛）；`InsufficientData` 分支。独立 ruby 模块，可最先写。
- **P20 — 候选产出（表格预览 + 人工粘贴，不扣库存）**：候选以表格呈现，不自动建实验 / 不写 stock；stock 不扣减不变量 spec。依赖 P18/P19。
- **P21 — 贝叶斯优化抽屉面板 + 审计**：UI wizard（目标 / 约束 / 范围 → 优化 → 预览 → 确认）+ `ai_audit_logs`（feature_id=AI-501）。依赖 P1/P18/P19/P20。
- **P22 — 端到端 spec**：request spec（权限 / 关闭开关 403）+ 抽取 → 优化 → 落 draft 整链（本模块不调 LLM，审计仍记）。

> 备注：AI-501 与 LLM 解耦（纯数值），但复用地基 P1 的会话/审计/抽屉外壳；审计照常落 `ai_audit_logs`。
