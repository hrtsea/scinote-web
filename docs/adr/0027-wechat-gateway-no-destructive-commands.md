# 0027 — 网关永不提供删除 / 归档 / 抹除类指令

> 适用范围：`addons/wechat_gateway` 的指令面。
> 依据：2026-09-24 盘问结论；GLP / 电子实验记录本的审计要求。
> 关联：0023（addon 总体，决策 4 真实用户身份）。

## Status

Accepted（2026-09-24）。守卫与文案一致性检查尚待实现。

## Context

这是一个**对话式**入口：用户在一句话的长度里下指令，误操作的成本远高于 Web 端——Web 端有一层确认弹窗、面包屑和可撤销的路径，聊天里只有一条已经发出的消息。

与此同时，这个 addon 的定位是 GLP 场景的实验记录采集：

- 记录必须**不可被静默销毁**；
- 记录必须以真实用户名义落库（ADR 0023 决策 4）；
- 一旦记录被收取到 SciNote，它就进入宿主的活动追踪与审计范围。

一个「发条指令就把实验删了」的通道，与以上三条同时冲突。

当前实现里唯一带「消失」含义的指令是 `/cancel`，它实际上只清掉本地草稿索引、**科学记录仍然存在于宿主**。这个语义是对的，但文案与直觉相反——用户会以为 `/cancel` 是撤销。

## Decision

**addon 的指令面永不提供删除、归档、抹除、还原类指令。** 任何不可逆变更必须回到 Web 端执行。

1. 不新增 `/del`、`/rm`、`/archive`、`/delete`、`/purge` 等任何同族指令，也不接受其别名。
2. `/cancel` 的语义保持「放弃本地草稿索引」，**绝不触碰宿主记录**；其回复文案必须**明示实验仍然存在**，不能只说「已取消」。
3. 「想在微信里删点什么」是一条**明确的用户诉求降级**：回复里给出「请到 Web 端处理」的可执行下一步，而不是静默忽略。
4. 路由层不再识别的任何删除类词形，按**隐式录入**处理（内容不丢），而不是报错——但帮助文本里不会出现它们。

### Considered Options

- **提供 `/archive <实验ID>` 软归档**（否决）：归档是不可逆状态的语义起点，一旦开了口子，「软」与「硬」的边界会在后续需求里被一点点推过去；且归档后的实验仍然会在列表里制造「我的记录去哪了」的困惑。
- **提供删除但加二次确认**（否决）：聊天里的「确认」只是多一条消息，不构成真正的摩擦；且把审核动作下沉到 IM 通道本身就与 GLP 分工相悖。

## Consequences

- 用户偶尔会问「怎么删」，因此需要一条稳定的、礼貌的拒绝路径，而不是让请求落空。
- `/cancel` 的文案是**唯一的防线**：一旦它说成「已取消」「已撤销」，用户就会误以为记录消失，转而在 Web 端寻找一个不存在的删除动作。
- 宿主侧的**软锁**（`/confirm`）不属于删除，保留；它冻结的是本地草稿索引，不是记录（见术语表「软锁」条目）。
- 本 ADR 约束的是**指令面**，不约束 addon 将来可能提供的只读管理 UI——但那样的 UI 若要出现，需要新的 ADR，而不是本条的例外。
