## 一、结论

官网「受监管环境（21 CFR Part 11 / GLP / GMP，GxP）」页面所列合规能力，**约 70% 已由本 fork 落地或具备基础**，且其中最关键、最刚需的**电子签名已作为 `esignatures` addon 完整实现并接入**（ADR-007，2026-09-01 实施进度：26 examples 0 failures、rubocop 0 offenses）。

剩余**真实代码缺口只有两项**：

1. **防篡改审计追踪（append-only / WORM 审计链）**——现有 `Activity` 仅为普通活动流（可改可删），不满足「cannot be edited or deleted」；已在 `PRODUCT_GAP_AND_PLAN.md` 列为 **G2（Addon B `audit_trail`）**，规划但未实现。
2. **电子见证（electronic witnessing）**——全仓 0 命中，属**本次新识别的完全缺失项**；建议作为 `esignatures` addon 的能力扩展（签名 + 见证双重责任链），不另起 addon。

其余页面条目（角色权限、封闭系统、唯一登录、会话超时、全量人类可读导出、归档、加密/2FA/SSO）均已具备；基础设施/合规声明类（每日备份、FedRAMP、ISO 27001、IQ/OQ 软件验证）属运维/SaaS，N/A。

## 四、缺失清单与开发计划（addon 形态）

### 缺口 A — 电子见证 electronic witnessing（❌ 新识别）

**判定**：官网明确列为 21 CFR Part 11 能力之一，但全仓 0 命中，完全缺失。

**设计（待 `/grill` 确认，遵循 铁律）**：作为 **`esignatures` addon 的能力扩展**，不另起 addon——见证与签名是同一责任链的上下游，复用 `SignatureService` 与哈希链原语最自然。

- **数据模型**：addon 自有迁移新增 `e_signature_witnesses`（`witnessable_type`/`witnessable_id` 多态指向 `e_signature_records`，`user_id`、`witnessed_at`、`meaning`、`witness_hash`）；append-only，无 update/delete。
- **服务**：`WitnessService.call(signature_record:, user:, meaning:)` 生成见证记录，哈希链接续该签名的 `signature_hash`（即见证链锚定到被见证签名）。
- **权限**：`addons/esignatures/app/permissions/**/*.rb` 增 `can_witness_record?`（复用核心 `can_manage_*` 分派，类比 `SignaturePolicy`）。
- **UI**：`app/overrides/*.rb` 在签名面板旁注入「见证」按钮，受 `can_witness_record?` 门控；无权限返回空串。
- **校验/导出**：`ChainVerifier` 扩展覆盖见证链；`ExportProof` 在导出证明中附加见证记录。

**垂直切片 Issue（建议）**
- **W1** — 迁移与模型 `e_signature_witnesses`（append-only）+ `Extends` 合并注册（不改动 `extends.rb` 本体）。
- **W2** — `WitnessService.call` + 哈希链接续 + spec（红绿）。
- **W3** — 权限 `can_witness_record?` + deface 入口注入见证按钮（门控）。
- **W4** — `ChainVerifier`/`ExportProof` 覆盖见证链 + 导出证明。

### 缺口 B — 防篡改审计追踪（⚠️ G2，Addon B `audit_trail`）

**判定**：与 `PRODUCT_GAP_AND_PLAN.md` 「G2 / Addon B」一致，规划未实现。本页「审计追踪不可编辑或删除」是合规硬要求，`Activity` 不满足。

**设计（addon 形态，详见 `PRODUCT_GAP_AND_PLAN.md` Addon B）**
- **B1** — 不可变审计存储：addon 自有表 + 哈希链写入，订阅关键写事件（复用 `Activities::CreateActivityService` 事件源或 observer），**不碰核心写路径**。
- **B2** — 校验工具：CLI/rake 定期校验哈希链完整性，异常告警。
- **B3** — 只读 UI：审计日志只读页，标注不可篡改属性。
- 与 ADR-007 哈希链原语共用（审计链可复用签名链同一 `H(prev_hash + payload)` 形式）。
- **实施前须补 ADR-00X**（追加到 `docs/ARCHITECTURE_DECISIONS.md` 第三节），记录「扩展哪个 `Extends` 键 / 订阅哪个核心事件 / 覆盖点风险」，对齐 `docs/agents/domain.md` ADR 约定。

## 六、风险

- **WORM 物理不可篡改超范围**：自托管仅靠应用层不可变 + 哈希链证明；DB/存储层 WORM 需基础设施能力，残留风险须在 rebase 时复核（ADR-007 已标注）。
- **哈希链锚定**：见证链须锚定到被见证签名的 `signature_hash`，避免独立成链导致责任链断裂。
- **与上游冲突**：若上游未来自实现签名/审计，本 addon 经 `deface`/`decorators` 的覆盖可能重复触发——覆盖点须随上游演进复核（同 ADR-007 风险）。
- **测试环境**：rspec 连 test 库 `scinote_test`，addon 表须建在 test 库；缺 `MAIL_FROM` 致全场失败；`pg_dump` 版本不匹配需带 `postgresql-client` 18 后复核 `db/structure.sql`（详见 `PRODUCT_GAP_AND_PLAN.md` 实施进度踩坑条）。
