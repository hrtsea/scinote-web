# 微信网关指令参考

> 范围：`scinote-web/addons/wechat_gateway` 的对话指令协议。
> 本文是**现有指令的事实清单**，对照 `lib/.../intake.rb`、`bind_command.rb`、`inbound.rb` 代码整理。
> 状态图例：✅ 已实现 ｜ 🟡 部分实现 ｜ 🔧 本次完善 ｜ 🧭 已定稿待实现 ｜ ⚠️ 已知限制

**本文按 SciNote 的实体层级组织**：`Project → Experiment → Task(MyModule)`。
每一层都按同一组动作排列：**新建 → 指定 → 查看 → 列举**；不属于任何一层实体的指令归到「跨层」。
命名规律见 §〇.2。

## 〇、一张表看清全部指令

### 1. 三级 × 四动作

| 层级 \ 动作 | 建 | 指定 / 设为当前 | 查看 | 列举 |
|---|---|---|---|---|
| **Project**（一级容器） | `/newproject` | `/setproject <ID>` | `/getproject` | `/listproject [n\|all]` |
| **Experiment**（二级容器） | `/newexp` | `/setexp <ID>`、`#<ID> 文本`<br>（后者仅本条有效） | `/getexp` | `/listexp [n]`、`/search <词>` |
| **Task / MyModule**（三级） | `/newtask` | `/settask <ID>` | `/gettask` | `/listtask <实验ID> [n]` |

**这张表暴露的事实**：

- **三级现在全齐**——Project / Experiment / Task 各有「建 / 指定 / 查看 / 列举」四件事，动词与实体名完全对齐（见 §三 命名规律）。
- **Task 层与 Project/Experiment 同规律**：`/newtask` `/settask <ID>` `/gettask` `/listtask`（见 §二.3）。
  **重要更正**：宿主里**文件、图谱、表格、结果的真实挂点都在 Task（MyModule）之下**——分别落在 `Result`（`result_texts` / `assets` / `tables`）、`Step`（步骤内 `assets`）、`RepositoryRow`（图谱行，直接 `belongs_to :my_module`）。
  `Experiment` 本身**只有** Overview `description` 和一张 `workflowimg`，并**没有** assets / results 容器。
  网关当前把纯文本**降级**追加到 Experiment / MyModule 的 `description` 字段（见 §四.3），这只是简化落点，不代表宿主数据结构；让微信端真正创建 `Result` / `Asset` / `RepositoryRow` 是独立的能力建设。
- `#<ID> 文本` 与 `/setexp` 的区别是**作用域**：前者只作用于本条消息，后者改变后续所有消息的落点（详见 `CONTEXT.md` §4「消息级指定 vs 会话定向」）。

### 2. 命名规律

| 规律 | 说明 |
|---|---|
| **`<动词><实体>` 四动作** | `/new<实体>` 建 · `/set<实体>` 设为当前 · `/get<实体>` 查看当前 · `/list<实体>` 列举 |
| 动词必须是这四个之一 | 不用近义动词（`use`/`show`/`query`/`switch`），也不用裸实体名做查看 |
| 一个操作只有一个名字 | 无别名。历史上存在过的别名已全部删除（见 §三） |
| 未被识别的 `/xxx` 不是错误 | 一律按**普通文本**录入处理，内容不丢 |

### 3. 越往下越依赖上层

每一层的「写」都需要先确定**上层容器**：

```
/newexp  需要一个 Project  ← 默认项目（/setproject 长期记住，或走引导现选）
/newtask 需要一个 Experiment ← 当前实验（/setexp）→ 默认实验(🧭) → 默认项目下的候选 → 引导
纯文本   需要一个 Experiment ← 同上
```

解析顺序是统一的：**显式 > 上下文 > 引导**（ADR 0028）。

## 二、指令详解

### 1. Project 级

#### 1.1 `/newproject <名称> [| 描述] [@起 ~止]` — 新建项目 🆕
- **行为**：在当前团队（默认目标项目所属 `team`）下调 `CreateProjectService` 建 `Project`，作者为绑定用户。名称必填；`|` 后可附描述。
- **起始日期自动填充**：未显式给 `@起始` 时，`start_date` **自动填为当前指令日期**（`Time.zone.today`，即发指令当天）。这与原生「Create new project」弹窗行为一致——打开弹窗时 Start date 预填今天。
  - 显式覆盖：`@YYYY-MM-DD` 写 `Project.start_date`。
  - 截止日期：`~YYYY-MM-DD` 写 `Project.due_date`（可选，不给则留空）。
  - `@`/`~` 后**必须紧跟日期**才解析，故描述里的 `@张三` 这类提及不会被误判为日期。
- **权限**：需 `can_create_projects?(@user, team)`；无权限时回复友好提示而非 500。
- **🔧 本次改造**：新建成功后**顺手设为你的默认项目**（建完马上在里面建实验是主路径），回复里会说明。团队来源：实例默认项目所属 team → 你的第一个 team（不再要求先配 `WECHAT_GATEWAY_PROJECT_ID`）。
- **示例**：
  - `/newproject 中试项目 | 2026Q4 中试` → `🆕 已新建项目 #55「中试项目」（起始 2026-09-24）…已设为你的默认项目…`（起始=今天）
  - `/newproject 中试项目 @2026-10-01 ~2026-12-31` → 起始 2026-10-01、截止 2026-12-31

#### 1.2 `/setproject <项目ID>` — 设置默认项目 🆕
- **行为**：把某项目设为你的**长期默认项目**（持久化到 `wechat_gateway_user_states`）。会先校验它存在、未归档且你有「创建实验」权限；不通过则拒绝并保留原值。
- **它是 `/newexp` 的隐式落点**：设过之后建实验不再需要任何交互；换项目用同一条指令再设一次。
- **示例**：`/setproject 55` → `✅ 默认项目已设为 #55「中试项目」；后续 /newexp 直接建在该项目下。`

#### 1.3 `/getproject` — 查看当前默认项目 🆕
- **行为**：显示当前默认项目；若该项目当前不可建实验会标注；未设置则引导用 `/listproject` + `/setproject`。

#### 1.4 `/listproject [n|all]` — 列项目 🆕
- **行为**：默认列**可新建实验**的项目（`readable_by_user` + `EXPERIMENTS_CREATE` 权限，跨你所属全部 team，未归档、按 `created_at` 倒序，默认 5 条）；`/listproject all` 列**全部可读**项目（含只读）。
  - 只列可建的：列出来就是为了建实验，列不能建的是噪音；`all` 只用于查找/核对。
- **示例**：
  - `/listproject` → `📁 可新建实验的项目（3）：\n#55 中试项目\n…\n设为默认项目：/setproject <编号>；看全部可读项目：/listproject all。`
  - `/listproject all 20` → 全部可读项目 20 条

### 2. Experiment 级

#### 2.1 `/newexp [标题] [@起 ~止]` — 新建实验草稿
- **行为**：在**当前默认项目**下调 `CreateExperimentService` 建实验，本地草稿索引指向它。
- **语法**：`/newexp [标题] [@起始日期 ~截止日期]`
  - 标题：省略则用默认 `微信记录-<user_id>`。
  - 日期：`@YYYY-MM-DD`（含可选 `HH:MM`，`~` 同理）写实验 `start_date`/`due_date`；`@`/`~` 后**必须紧跟日期**才解析（防误伤群消息 `@提及`）；非法日期被忽略、不报错。
- **🔧 本次改造（项目作用域）**：实验必须挂在某个项目下。
  - **有默认项目** → 直接建（沿用标题/日期），零额外交互。
  - **没有 / 默认项目失效** → **不建**，改为列 ≤10 个「可新建实验」的项目，等你回复项目编号；**标题与日期会暂存**，选完直接建，不用重打。回复 `0` 取消。
  - 选过的项目**长期记住**（存 `wechat_gateway_user_states.default_project_id`，按 SciNote 用户，跨 iLink/企微通道共享）。
  - 每次 `/newexp` 前预校验默认项目（是否被撤权/归档），失效则清空并提示重选。
  - 若你**一个可建实验的项目都没有** → 明确提示去 Web 端新建或找管理员授权，不空转。
- **完善点**：① 若已存在**未收尾的开放草稿**，回复提醒旧草稿仍开放、记得 `/done` 收尾，**不自动关闭**（避免静默孤立实验）；已锁定旧草稿不重复提醒。② 支持标题与起止日期入参。
- **示例**：
  - `/newexp` → `🆕 已开新实验草稿 #123。`
  - `/newexp PP配方A @2026-09-24 ~2026-10-01` → `🆕 已开新实验草稿 #124「PP配方A」（起始 2026-09-24，截止 2026-10-01）。`
  - 无默认项目时 → `📁 实验必须挂在某个项目下，请先选一个（回复项目编号，15 分钟内有效）：#12 PP配方开发 …`

#### 2.2 `/setexp <实验ID>` — 设置当前实验
- **行为**：校验实验存在且有权访问，把本地草稿索引切到该实验；后续消息/附件挂到这里。
- **效果**：把该实验的**所属项目设为你的默认项目**（「切到这个实验干活」=「这个项目是当前上下文」）。若该项目你没有建实验权限，则不覆盖默认项目并给出提示。
- **示例**：`/setexp 120` → `🎯 当前实验已设为 #120「…」，后续消息/附件将挂到这里…`
- **配套**：`/getexp` 查看当前实验（只读形态，对应 `/getproject` 之于 `/setproject`）。

#### 2.3 `/getexp` — 查看当前实验 🆕
- **行为**：显示当前草稿索引指向的实验；无当前实验时给下一步（`/newexp` 新建 或 `/setexp <ID>` 指定已有）。

#### 2.4 `#<实验ID> 文本` — 消息级指定
- **行为**：本条消息直接追加到 `#ID` 实验（先切换再追加文本），不影响后续默认草稿。
- **示例**：`#120 补充：温度设为 200℃`
- **与 `/setexp` 的区别**：`#` 是**一次性**的，`/setexp` 是**持续**的。这条尾巴最容易踩错。

#### 2.5 `/listexp [n]` / `/search <词>` — 查询
- **行为**：复用 `Experiment.search(user, false, q)`；`/listexp` 默认 5 条且可带数量参数，`/search` 限 10 条。
- **回复**：带编号列表，并提示「回复 #编号 即可挂接」。

### 3. Task 级（MyModule）

#### 3.1 `/newtask <实验ID> [任务名] [~截止]` — 新建任务 🆕
- **行为**：在**指定实验**（`Experiment`，必须存在且有权访问）下调 `CreateMyModuleService` 建 `MyModule`（任务），作者为绑定用户并自动加入任务成员。
  - 首个 token 必须为整数实验 ID，否则返回用法提示。
  - 任务名可省略（SciNote 给默认名）。
  - 仅支持 `~截止日期`（MyModule 表**只有 `due_date`，无 `start_date`**）；写 `MyModule.due_date`。提供的 `@起始` 会被忽略（MyModule 无该字段）。
- **副作用**：建完任务后把当前草稿切到该实验（`SessionDraftStore.put`），方便后续文本/媒体追加到同一实验。
- **示例**：`/newtask 120 平行样1 ~2026-10-01` → `🆕 已在实验 #120 下新建任务 #88「平行样1」（截止 2026-10-01）。当前草稿已切到 #120…`

> **🧭 既定改造（已定稿，尚未实现）**
>
> 目标实验不该让用户抄 ID。依据 **ADR 0028**（`docs/adr/0028-wechat-gateway-target-selection.md`），
> `/newtask` 将变更为 **`/newtask [任务名] [~截止]`** —— **行内 ID 被移除**，
> 目标按「**当前实验 → 默认实验 → 引导选择**」的顺序解析：
>
> | 情形 | 行为 |
> |---|---|
> | 已有当前实验 / 记住了默认实验 | 直接建（零交互，复用短期索引或长期值） |
> | 记住了默认项目、但没有当前实验 | 列 ≤10 个**可建任务**的实验，回编号 |
> | 连默认项目都没有 | 先列可建实验的项目，选完立刻列该项目的实验（两级串联） |
>
> 其它规则沿用 §二.2.1 的项目引导：纯数字且在候选内才算选择、`0` 取消、其它输入按普通消息处理（**内容不吞**）、
> 待选有效期 15 分钟；该项目下没有实验时**给下一步提示，不自动代建**。
>
> ⚠️ **届时的破坏性变更**：`/newtask 120 平行样` 里的 `120` 会被当作**任务名的一部分**，
> 而不是实验 ID。实现 ticket：`.scratch/wechat-gateway/issues/19–22`。

#### 3.1.1 `/settask <ID>` — 设置当前任务 · `/gettask` — 查看当前任务 🆕
- **行为（与 `/setproject` `/setexp` 同规律）**：`/settask <ID>` 把某任务（`MyModule`）设为当前落点（写入 `SessionDraftStore.task_id`）；`/gettask` 查看当前任务。
- **合法性**：`/settask` 先过 `visible_my_module`（存在 + 对当前用户可见），否则友好提示；并把它所属的实验设为当前实验、所属项目设为默认项目（与 `/setexp` 一致）。
- **落点分流**：设为当前任务后，后续纯文本/图片/文件追加落到该任务的 `MyModule.description`（降级落点，见 §四.3）；`/done`、`/cancel`、`/confirm`、`/unlock` 也以任务为作用对象。
- **🧭 注意**：宿主里**文件 / 图谱 / 表格 / 结果**的真实容器是任务下的 `Result` / `Step` / `RepositoryRow`（见上方领域模型），当前 `append_task_note` 仅追加到 `MyModule.description`，并未创建这些实体；让微信端真正创建它们属独立能力建设。
- **示例**：`/settask 88` → `🎯 当前任务已设为 #88「平行样1」；后续消息将挂到这里。`

#### 3.2 `/listtask <实验ID> [n]` — 列任务 🆕
- **行为**：列出指定实验下的未归档任务（`Experiment.my_modules.where(archived:false)`，倒序，默认 5 条）。实验 ID 必填（整数）。
- **示例**：`/listtask 120` → `📦 实验 #120 的任务（2）：\n#88 平行样1\n…`
- **说明**：属于 Task 级、但**依赖 Experiment 作参数**——这是容器层级决定的，不是随意设计。

### 4. 跨层指令

#### 4.1 录入（纯文本 / 图片 / 文件）—— 不是指令，但是主路径
- **行为**：未匹配任何指令的消息一律视为录入，追加到**当前实验**正文；无当前实验时自动建草稿。
- **容器解析**：当前实验 →（🧭 改造后）默认实验 → 默认项目下的引导 → 无项目先选项目。本条内容会暂存，选完自动写入。
- **冲击提醒**：正因为这条规则存在，**任何已被删除的指令写法都不会报错**——`/new …`、`/list …`、`/use …` 现在都会被安静地写进实验正文。这既是「内容不丢」的保证，也是误输入的代价。

#### 4.2 `/done` — 收尾 🔧
- **行为**：在实验正文追加「✅ 收尾于 <时间>（状态置为已完成）」，并调 `TimeTrackable#complete!` 写真实 `done_at`，使实验状态机计算为 `done`（可在 Web 实验列表**按状态筛选**）。随后清除本地草稿索引。
- **本次完善**：原实现只在正文写「🔒 完成于」时间戳行，导致 Web 端状态永远「未开始」、无法按状态筛选。现改为真实写入 `done_at`，状态与筛选器一致。
- **注意**：`done_at` 是实验级真实时间戳，非本地草稿软锁；`/confirm` 仍是仅拒绝追加的本地软锁。

#### 4.3 `/cancel` — 放弃本地草稿
- **行为**：仅清本地索引；实验仍留在 SciNote，需去 Web 端删除/继续编辑。
- **回复**：`🗑️ 草稿 #123 保留但不再追加…`

#### 4.4 `/confirm` — 软锁定 🔧
- **行为**：对本地草稿置 `locked=true`，追加「✅ 已确认 <时间>」行；此后文本/媒体/指派均被拒收。
- **本次完善**：回复明确区分「软锁（拒追加，实验仍开放）」与「/done（时间戳+收尾）」，并提示可用 `/unlock` 解除。
- **限制**：锁仅存于**进程内** `SessionDraftStore`，多 worker / 重启后丢失（同草稿存储的已知限制）。

#### 4.5 `/unlock` — 解除软锁 🔧 新增
- **行为**：清除本地 `locked`，追加「🔓 已解锁 <时间>」行，恢复追加能力。
- **回复**：`🔓 实验 #123 已解除锁定，可继续追加；发 /confirm 重新锁定或 /done 收尾。`
- **边界**：无草稿 / 未锁定时分别给出明确提示，不报错。

#### 4.6 `/bind <绑定码>` — 账号绑定 🔧
- **主路径（私聊文本）**：`BindCommand` 解析 → 校验码（一次性+过期）→ 建 `WechatUserBinding(wechat_id↔scinote_user_id)`。
  - 已绑定 → `这个微信/企微账号已经绑定过啦…`
  - 码无效/过期 → `绑定码无效或已过期，请在 SciNote 设置页重新获取。`
  - 成功 → `绑定成功！… 🎉`
  - 本次完善：`create_binding` 异常（罕见竞态/重复）兜底为友好提示而非 500。
- **备用路径（HTTP `/bind/:code`）**：🔧 修复——原 `confirm_by_code` 不存在会 500。现改为**绑定码有效性落地页**：`valid` 提示回聊天发 `/bind <码>`（页面无法识别微信身份）；`used/expired/none` 分别提示去设置页重生成。

#### 4.7 `/admin [词]` — 管理员查询
- **行为**：需 `InstanceAdmin.admin?(user)`；在其所属 team 内查 `Experiment`（绕过 per-user 可见性）。空结果给提示。

#### 4.8 `/book <设备ID> <起ISO> <止ISO>` — 设备预约
- **行为**：校验 `Repository.equipment_booking_enabled?` 与权限，建 `CalendarEvent(event_type: equipment_booking)`。
- **示例**：`/book 12 2026-09-24T14:00 2026-09-24T16:00`

#### 4.9 `/help` — 指令发现入口 🔧 新增
- **行为**：输出全部指令与一行的用法清单（见 §一），无参数或带多余参数均返回。
- **待办**：按 §〇 的层级分组输出（`ticket 17`）。

> **路由修复（此前）**：原 `route_command` 对建实验指令仅做精确匹配，导致 `/newexp 标题` 这类「带参数」指令被当作普通文本而丢失标题/日期语义。现改为对 `/newexp` 增加 `start_with?` 前缀分支，带参也能正确解析；同时把更具体的 `/listproject`/`/listtask`/`/newproject`/`/newtask` 前缀判断置于通用前缀之前，避免命令前缀冲突。

## 四、已知限制 / 待消项

1. **草稿存储进程内**：`SessionDraftStore` 为内存 Hash，多 worker / 重启丢态（含 `/confirm` 软锁）。生产应换 Redis/DB。
   （**注意**：默认项目与待选 pending **不是**进程内——它们已落 DB `wechat_gateway_user_states`；迁移尚未执行，见下。）
2. **iLink 真机回包未接**：仅留钩子，待接 iLink 主动消息 API。
3. **媒体真附件未挂接**：`upload` 仍以正文占位记录（`📎 附件：…`），真实 ActiveStorage 挂接见 Ticket 05。
4. **Formulation 成分落地**：`engine.rb` 未传 `material_resolver`，PP 配方 component 暂未落 `FormulationComponent`。
5. **MyModule（任务）创建**：✅ 已通过 `/newtask` 实现（走 `CreateMyModuleService`），并自动把当前草稿切到该实验。Result 级条目创建仍未实现。
6. **Task 层「设为当前 / 查看当前」已补齐**：`/settask` `/gettask`（与 Project/Experiment 同规律），当前落点解析已支持 Task（见 §二.3）。
   **落点澄清**：「当前落点」下探到任务后，纯文本追加落到 `MyModule.description`（降级）。但宿主里**文件 / 图谱 / 表格 / 结果**的真实容器是 Task 下的 `Result` / `Step` / `RepositoryRow`（见上方领域模型），微信端尚未创建这些实体——属独立能力建设，不是当前 bug。
   ⚠️ 历史错误说法已纠正：此前文档称「所有追加都落到 Experiment.description」「写入止于实验级」——这是把网关的**降级落点**误当成宿主数据结构。Experiment 本身无文件/结果容器。
7. **环境阻塞**：本地 SciNote 实例未起（C 盘满/Docker 未装），`service user:` 语义、指派 create 语义、企微群 @ 真机字段、以及新增的 `CreateProjectService`/`CreateMyModuleService` 权限与字段（如 `MyModule.due_date` 写入）仍需实例核实。
8. **待执行迁移**：`20260924120000_create_wechat_gateway_user_states.rb` **尚未运行**（本地无实例）。上线前须跑 `rails db:migrate` 并同步 `db/structure.sql`；否则所有 `/newexp`、`/setproject` 会报「表不存在」。设计见 `docs/开发计划/wechat-gateway/项目选择流程设计.md`（Part I 已实现 / Part II 待实现）。
