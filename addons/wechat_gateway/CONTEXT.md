# 微信网关 Addon 术语表（CONTEXT.md）

> 本文件是 `addons/wechat_gateway` 的**唯一术语来源（glossary）**，不含实现细节、不含变更流水账。
> 实现决策见 `docs/adr/0023`（addon 总体）、`0024`（任务指派语义）、`0025`（指令权限校验）、`0026`（Team 作用域）、`0027`（无删除指令）、`0028`（目标选择：显式 > 上下文 > 引导）。
> 宿主 SciNote 的精确语义以宿主源码为准；术语若与宿主冲突，以本表为准并在 ADR 记录。

---

## 一、插件与边界

- **微信网关 addon（wechat_gateway）**：本插件的 Rails Engine 形态，命名空间 `Scinote::WechatGateway`。独立于宿主核心，可整体启停。
- **原生 SciNote（host）**：被挂载的 SciNote 主应用。实验 / 任务 / 项目 / 权限 / 审计追踪由宿主拥有；addon **不以任何方式修改宿主表结构与业务实体定义**。
- **零侵入（zero-intrusion）**：不修改宿主的 `app/`、`config/routes.rb`、`config/application.rb`、宿主迁移。addon 通过 Engine 自注册路由、视图覆盖、initializer 注入接入。
- **启停（enable / disable）**：关闭后引擎不挂载路由、不解析消息，系统完全退化为原生 SciNote。
- **进程内（in-process）**：addon 与宿主同进程，直调宿主 service / 模型，因此**免逐用户 OAuth token**（见 ADR 0023）。
- **addon 自有表（addon-owned tables）**：addon 需要持久化状态时，**只新增自己的表**，不向宿主表加列。

## 二、通道与入口

- **iLink（私聊 DM）**：腾讯官方 iLink Bot API。平台不向 bot 投递普通微信群事件，**仅私聊可用**。
- **企业微信自建应用（WeCom）**：官方合规入口，能收群消息（含文件 / 图片 / @），是**群聊 + 组长派任务的唯一通道**。
- **Hermes（历史）**：早期独立网关的群消息来源。**已不再依赖**，仅作参考。
- **双通道统一收敛**：两条入口在 addon 内统一产出 `Message`，下游写入逻辑完全共用。
- **platform**：`'ilink'` | `'wecom'`，绑定与路由的判别维度。

## 三、身份与绑定

- **wechat_id**：微信 / 企微侧用户标识（iLink 为 openid/昵称；企微为稳定 `userid`）。
- **scinote_user_id**：SciNote 真实用户主键。写入时 `created_by` 置为此值——**审计链的唯一锚点**。
- **绑定（binding）**：`wechat_id + platform → scinote_user_id` 的映射关系。同一 SciNote 用户在两个通道是**两行**（唯一键为 `[wechat_id, platform]`）。
- **绑定码（BindCode）**：一次性 + 过期 + 绑到生成时的 SciNote 用户，防冒领。用户发 `/bind <码>` 完成绑定。
- **BindingResolver**：按 `(wechat_id, platform)` 解析 `scinote_user_id`；未绑定返回 `nil`。
- **未绑定态（unbound）**：用户尚未建立绑定，除 `/bind` 外所有能力不可用。

## 四、消息（Message）

- **Message（统一消息）**：两通道归一后的结构，承载文本、媒体、提及、来源平台、接收方等字段。
- **提及（mention）**：群消息中被 @ 的用户，用于组长派任务（F6）。
- **录入（append）**：把一段文本 / 媒体挂到某个实验的过程。addon 的核心动作。
- **隐式录入（implicit capture）**：**未匹配任何指令**的纯文本 / 媒体一律视为录入内容。它不是指令，但会被可靠地落库——**内容绝不丢弃**。
- **消息级指定（message-level targeting）**：`#<实验ID> 文本` —— 只决定**这一条消息**的落点，**不改变后续消息的默认落点**（ADR 0025 语义之一）。
- **会话定向（session targeting）**：`/setexp <实验ID>` —— 改变**后续所有消息**的默认落点，直到被再次改变。

> **二者的区别是本 addon 最容易误用的两条尾巴**：消息级指定是「一次性」，会话定向是「持续」。

## 五、指令系统（Command）

- **指令（Command）**：以 `/` 开头的显式控制消息。指令**不产生录入内容**（除 `/newexp` 等同时携带内容的形式）。
- **指令层（Command Layer）**：指令按职责分层，层决定它能接受什么、落到哪里。

| 层 | 名称 | 职责 | 成员 |
|---|---|---|---|
| **L0** | 通道层 | 建立身份；**未绑定也可用** | `/bind` |
| **L1** | 作用域层 | 决定「写在哪里」 | `/setproject`、`/getproject`、`/setexp`、`/getexp`、`/listproject` |
| **L2** | 创建层 | 新建实体；**目标容器由目标解析顺序决定** | `/newexp`、`/newproject`、`/newtask` |
| **L3** | 会话草稿层 | 管理当前草稿与收尾 | `#<ID>`、`/done`、`/cancel`、`/confirm`、`/unlock` |
| **L4** | 查询层 | 只读遍历 | `/listexp`、`/listtask`、`/search` |
| **L5** | 特权层 | 越出个人可见范围的受控能力 | `/admin`、`/book` |

- **目标解析顺序（resolution order）**：创建类指令确定「写到哪里」的唯一规则 —— **显式 > 上下文 > 引导**。上下文是从短寿命到长寿命逐级回落（当前实验 → 默认实验 → 默认项目），全部落空才进入引导（ADR 0028）。
- **`<动词><实体>` 命名（verb-entity naming）**：指令名一律是「四个动词之一 + 实体名」，动词只有 `new`（新建）/ `set`（设为当前，写）/ `get`（查看当前，读）/ `list`（列举候选）。例如 `/newproject`、`/setproject`、`/getproject`、`/listproject`。不在清单里的动词（如历史上的 `/use`）一律不采用。

- **规范名（canonical）**：每个操作**只有一个名字**。助记不再靠别名堆叠，而靠 `/help` 按层分组呈现。
- **无别名（no aliases）**：同一操作不提供第二个写法——包括「看似自然的缩写」和「从上下文猜意图」的隐式形式（例如 `/project <ID>` 顺手当作设置默认项目）。第二条尤其容易被无意引入，因为它写在正则里而不是清单里。
- **未识别的斜杠串不是错误**：任何不在规范名清单里的 `/xxx` 都按**隐式录入**处理，内容不丢。
- **无删除指令（no destructive command）**：addon **永不**提供删除 / 归档 / 抹除类指令，任何不可逆变更必须回到 Web 端执行（ADR 0027）。
- **帮助（help）**：`/help`。按指令层分组输出，**每层的每一项都要说清「会落到哪个实体」**。

## 六、作用域（Scope）

- **Team（团队 / 租户）**：多租户根，所有宿主业务实体强约束 `team_id`。
- **Project（项目）**：一级容器，归属一个 Team。是**实验的唯一合法落点**——实验必须挂在某个项目下。
- **Experiment（实验）**：二级容器，归属 Project。addon 的核心写入目标。
- **MyModule（任务 / Task）**：三级容器，归属 Experiment。**宿主 UI / REST / 指令一律对外称 `Task`；模型实体恒为 `MyModule`**（ADR 0024）。阅读代码时不要把 Task 当成独立模型。
- **默认项目（default project）**：用户级长期作用域，按 `scinote_user_id` 存储，**同一用户在 iLink 与企微两通道共享**。它是 `/newexp` 的隐式落点。
- **实例默认项目（instance default project）**：实例级配置提供的回落值；**用户一旦显式选择过项目，用户级优先**。
- **默认实验（default experiment）**：用户级长期记住的**当前实验**，同样跨通道共享。它是 `/newtask` 与追加录入的隐式落点；**短期索引是它的缓存，不是另一个概念**（见下一条与 §7）。
- **待选（pending）**：临时的一次性**单步**等待态，带有效期（默认 15 分钟）。用户在此状态下回复编号才算选择；多条候选之间靠「选完立刻写下一个待选」**串联**，而不是存一只队列。已知步骤：`select_project`（选项目）、`select_experiment`（在某项目下选实验）。
- **可建（creatable）与可读（readable）**：**可读 ≠ 可建**。清单的过滤标准是「列出来就是要拿来建的」——项目用「创建实验」权限过滤，实验用「创建任务」权限过滤。
- **Team 作用域策略**：addon **不引入 Team 一等状态、不提供 team 切换指令**。候选可跨用户所属的全部 Team 收集，但**呈现时按 Team 分组**；Team 的隐式选择由「默认项目」承担——选定了默认项目即选定了 Team（ADR 0026）。

## 七、草稿、收尾与锁定

- **当前草稿（working draft）**：当前录入的默认落点实验，也称「当前实验」。它是**一个索引**，不是一个实体状态。
- **短期索引与长期值**：同一「当前实验」的两种存放寿命——进程内存是长期值（`默认实验`）的**缓存**，不是第二个真值来源。唯一解析入口负责对齐：先读短期索引，落空则从长期值**校验后恢复**并写回（ADR 0028）。
- **恢复（restore）**：从长期值重建短期索引的过程。**校验在前**（可见 + 未归档 + 对应写权限），失效即清空而非静默接管；且必须在回复里明示，让恢复成为一次可见事件。
- **草稿索引的生命周期**：短期。多进程 / 重启后可能失效，失效时尝试按上一条恢复。
- **软锁（soft lock）**：草稿级本地状态，锁定后拒收追加。**它只冻结本地索引，不代表实验在 SciNote 被锁定**——宿主实验并无只读强锁。
- **收尾（completion）**：写入真实完成时间，宿主据此把状态计算为「已完成」。**收尾才是实验的真实终结动作**，与软锁无关。
- **取消（abandon）**：丢弃本地草稿索引，**并清除长期默认实验**（否则下一条消息会把取消悄悄恢复）。**被丢弃的实验仍然存在于 SciNote** —— 永远不会因取消而消失（ADR 0027）。

## 八、权限

- **真实用户身份（created_by）**：记录必须落在真实操作人名下，不挂名 bot。这是 GLP 的硬要求。
- **可见性校验（visibility gate）**：任何**按 ID 定位宿主实体**的指令，都必须先确认该实体**对该用户可见**。凭 ID 直取是不允许的（ADR 0025）。
- **读权限与写权限（read vs write）**：能读不代表能写。追加、收尾、建任务等**写动作需各自对应的宿主权限**，缺权限必须给友好提示而非报错。
- **项目级创建权限（create permission）**：判定一个项目能否承接新建实验的唯一标准。
- **管理员查询（F9）**：受控的跨用户可见范围查询，需实例管理员权限。
- **设备预约（F10）**：预约行为受宿主设备预约开关与目标仓储权限约束。

## 九、宿主实体（Gateway 视角的精简定义）

> 仅列出 addon 会写入或读取的宿主实体。完整语义以宿主源码为准。

- **User（用户）**：系统用户，持有第三方身份映射与 API 凭据。
- **UserIdentity（身份映射）**：宿主自带的第三方身份表。addon **刻意不复用**它，改用自有绑定表（ADR 0023）。
- **Protocol（协议）**：方法 / 步骤集合，归属 MyModule。
- **Step（步骤）**：协议步骤，直挂协议。
- **Repository / RepositoryRow（库存表 / 物料行）**：表格化知识库；物料行承载物料主数据，被配方组成复用。
- **Formulation（配方）**：由另一 addon 提供的一等实体，归属 Team；由多个「配方组成」与若干「配方性质」构成。
- **FormulationComponent（配方组成）**：物料行 + 用量 + 单位。
- **FormulationProperty（配方性质）**：性质名 + 实测 / 目标值 + 比较符。
- **Result / Asset（结果 / 附件）**：实验 / 任务的结果与版本化附件。
- **设备预约（EquipmentBooking）**：日历事件的特化形态。

## 十、Avoid（明确避免的用法）

- ❌ 把 `MyModule` 读作独立的 `Task` 模型 —— Task 只是对外名（ADR 0024）。
- ❌ 认为「网关不新建 Project」—— 已过时，addon 可新建项目。
- ❌ 把「软锁」当成宿主强锁，或用软锁表达实验的真实状态 —— 真实状态由**收尾**写入。
- ❌ 认为 `/cancel` 会删除实验 —— 它只丢本地索引，实验永存（ADR 0027）。
- ❌ 提供 `/setteam` 之类的 Team 切换指令 —— Team 由默认项目隐式决定（ADR 0026）。
- ❌ 凭 ID 直取宿主实体而不走可见性校验（ADR 0025）。
- ❌ 混用三种寿命：**默认项目**（长期，用户级作用域）、**默认实验**（长期，用户级当前实验）、**当前草稿**（短期缓存）—— 短期只是长期的缓存，不得各自为政。
- ❌ 新增别名（含写在正则里的隐式形状）；同一操作永远只有一个名字。
- ❌ 用四个动词（`new` / `set` / `get` / `list`）之外的词命名指令（历史上的 `/use` 已改名为 `/setexp`，查看类已从裸实体名改为 `/get<实体>`）。
- ❌ 新增未经登记的规范名——`/help` 与本文档必须同期更新。
- ❌ 把「待选」做成队列或多步数组 —— 它是**单步**的，多级引导靠串联表达。
- ❌ 为消除空候选而**自动代建容器** —— 用户会在 Web 端看到自己不认识的容器，而网关不提供删除。
- ❌ 目标不明时靠「猜偏好」或静默回落到某个容器 —— 一律停在引导（ADR 0028）。
