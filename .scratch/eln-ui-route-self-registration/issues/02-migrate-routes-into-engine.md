# 02: 整块迁移 30 条路由并保持全绿

**What to build:** 把 ELN UI 的 30 条路由从宿主 `config/routes.rb` 整块搬进 addon 自己的路由定义，由引擎自注册。迁移完成后，宿主文件里不再有任何 ELN UI 路由，而**所有对外 URL 与具名 helper 名逐字不变**——书签、邮件通知里的既有链接继续可用，前端与 payload 一行都不用改。

**Blocked by:** 01 — 建立路由基线与引擎自注册骨架

**Status:** ready-for-agent

- [ ] 30 条路由的「动词 + 路径 + helper 名」三元组与 01 建立的基线逐一相等，数量仍为 30，无新增 / 缺失 / 改名
- [ ] 逐条 recognition 到预期 controller 动作（专门挡住"路由匹配得上但引用了不存在的 controller"这一静默 500）
- [ ] 宿主 `config/routes.rb` 不再含任何 `scinote/eln_ui/*` 路由
- [ ] 宿主 url_helpers 上所有既有具名 helper 仍可调用，且生成路径与迁移前逐字相同（payload 内 11 处全限定调用点零改动）
- [ ] helper 转发清单由 01 的基线生成，不是手写誊抄
- [ ] ELN UI 全部 11 个页面实测可达：项目详情、项目列表、资源中心、申请详情、任务详情、实验详情、通知中心、审批人、消耗核销、归档导出、工作台
- [ ] 项目指标 CRUD 四条（新增/更新/删除/达标切换）实测可达
- [ ] 6 张表的服务端网格端点实测可达，且 GET 与 POST 双动词均生效
- [ ] 项目列表 V1 孤儿路由仍可达（不在生产路径，但不得在迁移中丢失）
- [ ] 迁移后路由排在宿主 `resources :projects` 之后（append 的必然结果），已逐条验证可达，未依赖"顺序无关"的假定
- [ ] ELN UI 前端无感：无需改动任何 Vue 源码或 webpack entry

## 补充说明

- **必须整块一次性搬，不分批**。宿主文件里 ELN UI 路由块与 workbench 的那条边界清晰、中间无其他 addon 路由交错，可整块搬走。分批会产生"部分路由在引擎、部分在宿主"的双源中间态，这类双源曾导致同一份逻辑被执行两遍。
- 迁移涉及 30 条路由重排，**建议一次性提交**，避免中间态被合入。
- 引擎内路由的写法有两个已验证的陷阱（access_control 侧已踩过并留注释）：因 `isolate_namespace` 生效，控制器名**不能**再带命名空间前缀，否则双层前缀导致 recognition 报 missing controller；路由路径**不能**带前导斜杠，否则控制器名校验直接抛异常。
- 挂载点保持根路径。对外 URL 必须与现状逐字一致，这是本 ticket 的第一验收标准。
