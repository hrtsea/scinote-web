## 要新增的断言

| 场景 | 断言 |
|---|---|
| 三类弹层打开 | 日期字段是日历控件（有 `data-e2e`），不再是原生分段数字框 |
| 弹层完整性 | 点开日历 → 月历元素可见**且未被父容器裁剪**（元素 bounding box 完整在视口内、可见面积未被裁） |
| 点选 | 点某天 → 输入框值为 `YYYY-MM-DD`，弹层关闭 |
| 键入 | 输入框接受键入并归一为 `YYYY-MM-DD` |
| 清空 | 值变 `''`，占位提示回来 |
| 🔴 请求参数 | 设定筛选日期后**抓网络请求**，断言 `filters[start_date_from]` 原样发出 `YYYY-MM-DD` |
| 🔴 无时区偏移 | 断言发出的是**用户所点的那个日期**，不是前一天（东八区UTC 偏移回归的主要防线） |
| 列表联动 | 筛选生效后行数变化 |
| 区间反了 | 起始 > 截止 → 出现警告态，**列表仍能刷新、导出仍能点**（不阻断） |
| 预定联动 | 点选新日期 → 相邻「· 周X」后缀同步；清空 → 后缀消失（**不出现「周undefined」或悬空的「· 周」**） |
| 持久化 | 行操作弹窗选日期保存 → 刷新后列表行日期列不再是 `—` |
| 旧渲染器 | 旧版列表页的日期弹层未被 AG Grid 裁剪/遮挡；且**权限三层判定仍生效** |
| 无回归 | 全部页面 0 JS 错误、0 失败请求（沿用脚本已有基线） |

## 沿用脚本既有约定（不要重新发明）

- **认证**：`tooling/scripts/mksession.rb` 在容器内现签 Warden 会话（不动明文口令），`context.addCookies` 注入。**不要用 `extraHTTPHeaders`**。
- **会话不可复用**：容器每次重启后必须重签，否则 403 而非跳登录。
- **cookie 值不能 URL 解码**：文件里的 `%2B` 是原样值。
- **浏览器**：系统 Edge（`playwright-core` + Edge，不是 Chrome）。
- **五项基线**：HTTP 状态 + 挂载 + DOM 长度 + console 错误 + 失败请求。

## 硬约束

1. **只扩展，不重构**。脚本已跑通 6/6，改动不得让既有 6 个页面的断言失效。
2. **断言外部行为，不断言实现细节**。不断言组件内部的 ref 名/computed 名/VueDatePicker 实例字段 —— 那些是实现细节，重构就该能变。
3. **每条断言要有清晰失败信息**。日期 bug 大多是「静默差一天」或「弹层被裁」，报错信息必须能直接看出是哪一种。

- 0 JS 错误、0 失败请求

## 备注

- 「故意制造一次失败」这条不是形式主义。日期类 bug 最大的特征就是**静默**（筛选照跑结果照出，只是边界错了）。一条恒真的断言等于没有断言。
- 跑脚本前确认容器已重启且会话已重签，否则会以 403 失败，看起来像日期功能坏了。
