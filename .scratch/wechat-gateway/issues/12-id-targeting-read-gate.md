# 12 — 读侧指令接上可见性闸门（`/setexp`、`#<ID>`、`/listtask`）

**What to build:** 把每一条**按 ID 定位实体**的读侧指令换成走 ticket 11 建立的闸门原语，并把失败转成面向用户的文案。

**Why:** 闸门建在写入层，但指令层仍需保证「每条指令都真的走了它」——漏接一条等于白做。`/setexp` 与 `#<ID>` 是**最容易被撞的两条**：用户直接把列表里看到的编号打过来。

**ADR:** 0025｜**针对 User Story:** 「我发 `/setexp 别人的实验ID` 应该被告知不可访问，而不是把内容写进去」

**Blocked by:** 11

**Status:** ready-for-agent

- [ ] `/setexp <实验ID>` → 走闸门；不可见时不改变本地草稿索引（**先校验再切换**，不要切完了才发现没权限）
- [ ] `#<实验ID> 文本` → 走闸门；本条内容不得落到不可见实验
- [ ] `/listtask <实验ID>` → 先验证实验可见，再列其任务
- [ ] 三条的错误文案统一：说清「不存在或无权访问」+「发 /listexp 看你能访问的实验」
- [ ] 回归：确认不存在任何绕过闸门直接 `find` 的残留路径（全仓搜 `Experiment.find` / `Project.find`）

**验收：** 越权 ID 用例对三条指令均返回同一形态的友好提示，且本地草稿索引在 `/setexp` 失败时保持原值。
