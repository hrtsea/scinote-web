# 18 — 无删除指令：守卫 + `/cancel` 文案纠错

**What to build:** 把 ADR 0027 的禁令变成可被机器验证的守卫，并纠掉当前唯一一处「看起来像删除」的文案。

**Why:** ADR 不落到守卫里就只是纸面约束——哪天有人顺手加个 `/del` 不会有人拦。而当前 `/cancel` 的回复是「🗑️ 草稿 #N 保留但不再追加」：措辞带删除符号，用户极容易读成「已删除」，随后去 Web 端找一个不存在的删除动作。这条文案是用户与「不可销毁」之间唯一的防线。

**ADR:** 0027（永不提供删除 / 归档 / 抹除类指令）

**Blocked by:** None

**Status:** ready-for-agent

- [ ] `/cancel` 文案去掉 🗑️ 语义符号，明确说「**实验仍在 SciNote 中保留**」+ 给出去 Web 端继续编辑的去向
- [ ] `/cancel` 绝不触碰宿主记录（复核现值，加断言锁死）
- [ ] 新增守卫测试：穷举 `/del`、`/rm`、`/archive`、`/delete`、`/purge` 及其常见别名，断言它们**不被识别为指令**（按隐式录入处理，内容不丢），且不产生任何宿主副作用
- [ ] `/help` 中不会出现任何删除类词形（配合 ticket 17）
- [ ] 术语表 Avoid 条目与本 ticket 双向引用

**验收：** 守卫测试在有人新增删除类指令时变红；`/cancel` 回复中含明确的「保留」字样且不含删除符号。
